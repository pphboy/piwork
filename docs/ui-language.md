# piwork 浏览器 UI 语言

本文是仓库浏览器界面的视觉依据。它规定界面**看起来如何**：颜色、文字、密度、边界、控件状态与窄屏表现。页面内容顺序、按钮位置和文案由 [产品语言](product-language.md) 规定。当前首个实现是 `apps/console`；以后新建或调整浏览器界面也按本文检查。终端 CLI 不使用这里的 CSS 令牌。

## 气质与适用原则

piwork 管理界面应是安静、精确、紧凑的技术工作台。借鉴 GitHub Settings 的清晰 section，以及 Linear 对内容焦点和低噪音边界的处理；根据 piwork 的管理任务重新设计，不复制它们的品牌界面。

- 页面以浅蓝灰承托信息，白色 section 承载任务；顶栏冷白淡蓝，始终让内容比导航更醒目。
- 只用一种亮蓝作为品牌交互强调，主要给当前导航、焦点、链接和主要动作。错误、警告和危险操作使用各自语义颜色。
- 边框用于分组和分隔；默认没有投影。列表使用行与分隔线，不为每条记录叠加卡片。
- 不使用紫蓝渐变、毛玻璃、深色大顶栏、大尺寸指标卡、营销插画、过度留白或靠颜色单独传达状态。

## 颜色令牌

以下语义名和值是默认浅色主题的基准。当前实现位于 `apps/console/public/style.css` 的 `:root`。新页面先使用相同角色；确有不同需求时说明原因与替代规则。

| 令牌 | 值 | 使用位置 |
| --- | --- | --- |
| `--ui-canvas` | `#F5F8FC` | 页面背景 |
| `--ui-header` | `#F8FBFF` | 顶栏 |
| `--ui-surface` | `#FFFFFF` | section 与输入区 |
| `--ui-border` | `#DCE7F2` | section 边界与行分隔 |
| `--ui-control-border` | `#BAC9D8` | 输入、次要按钮边界 |
| `--ui-text` | `#1B2634` | 标题和正文 |
| `--ui-muted` | `#526477` | 帮助文字、元数据 |
| `--ui-accent` | `#0969DA` | 主要动作、链接、焦点、当前导航 |
| `--ui-accent-hover` | `#0759BA` | 强调控件悬停 |
| `--ui-accent-soft` | `#EAF3FF` | 当前导航、低强调信息背景 |
| `--ui-danger` | `#B42332` | 错误文字与危险操作 |
| `--ui-warning` | `#8A5A00` | 警告文字 |

语义反馈使用浅底色加文字说明。正常、警告、错误都必须能从文字判断；不能只换边框或徽标颜色。技术 ID 与代码块保持中性底色，使蓝色仍指向可操作内容。

## 字阶、密度与边界

| 元素 | 基准 |
| --- | --- |
| 正文 | 14px，行高 1.5，系统无衬线字体 |
| 页面标题 | 22px，紧接页面内容 |
| section 标题 | 16px，明确低于页面标题 |
| 辅助文字 | 12–13px，使用 `--ui-muted` |
| 间距 | 以 4px 为基数，常用 8、12、16、20px |
| 顶栏 | 目标高度约 56px，底部一条淡边界 |
| 内容宽度 | 所有管理页及详情页共用最大 1100px 页面轨道；同级一级卡片占满轨道 |
| section | 白底、1px 淡边界、6–8px 圆角；桌面内边距 16–20px，窄屏 12px |
| 输入与按钮 | 单行控件至少 34px 高，6px 左右圆角 |
| 表格 | 行高目标 40–44px，使用行分隔线 |

默认 section 无阴影。将来若出现覆盖内容的浮层，可单独采用极轻阴影；普通列表和设置区不用阴影制造层次。嵌套内容优先用标题、缩进和分隔线表达关系，不套第二层完整 section 边框。

## 内容容器与表单网格

顶栏内容与页面外层共用最大 **1100px** 的页面轨道。`Status`、`Users`、`Runtime`、`Default Work`、`Skills`、`Packages`、`Find Operation` 及其详情的页标题、说明和所有同级一级 section 共用左、右边界。一级卡片填满轨道；不能因为它承载设置、查询、列表或详情而改变外部宽度。登录页也使用该外层轨道，但登录标题、说明和单任务卡片在其中居中，内层最大 **420px**，保持单列；登录例外不用于任何已登录页面。屏幕比轨道窄时，外层同步收缩到视口扣除页面内边距的可用宽度。详情摘要与技术内容若需要较窄的阅读宽度，在同一张卡片内部约束。

一级卡片的宽度用于建立页面秩序；其中的表单字段、说明文本和技术内容各自控制行宽。字段不因外部卡片变宽而被拉长，较宽的表格只在自身容器滚动。长名称、来源、Operation ID 和代码在本行或局部区域换行或滚动，完整原文仍可读取或复制；任何长文本不得撑宽单张卡片、遮挡行操作或造成整页横向滚动。显示内容的先后与全文访问方式见[产品语言](product-language.md)。

除登录外，桌面管理表单统一使用 **176px 标签列 + 16px 列间距 + 最多 520px 控件列**，内容网格最多 712px，始终位于所属卡片内部。每一行的标签在标签列；输入、选择器、文本区、文件选择、复选框及其字段组在控件列。字段帮助、字数计数、校验错误和提交按钮与对应控件共享左边界；字段组外框不能相对其他控件再缩进。section 标题与 section 内容左边界对齐，表单末尾的主要按钮对齐控件列。宽卡片右侧的余量保持空白，不拉长字段或填入装饰性侧栏。

当 section 内宽度不足以容纳两列时，管理表单统一折为单列：标签在控件上方，控件、帮助、错误和动作共用左边界和可用宽度。360px 宽屏必须采用该布局，连续一级卡片也必须共享左右边界；文件选择、长文本和复选框不撑开页面。不能靠逐个字段的任意 margin 或绝对定位模拟对齐。检查时分别比较浏览器中一级卡片的左右边界，以及表单各元素的实际边界，而不只检查“没有横向滚动”。

## 容器层级与局部溢出

以下角色适用于现有和后续浏览器管理界面。同一角色沿用同一宽度和溢出规则，内容职责见[产品语言](product-language.md#容器职责与内容归属)。加载、空、失败、提交中和未知结果只改变所属容器内部，不改变一级卡片宽度。

| 容器角色 | 桌面几何与溢出 | 360px 与放大后的行为 |
| --- | --- | --- |
| 顶栏、导航、页面标题与说明 | 顶栏内容和页面共用 1100px 外层轨道；标题及说明占满轨道并与一级卡片对齐 | 轨道随可用宽度收缩；导航可换行，不推宽页面 |
| 一级 section：状态、列表、设置、上传、查询、详情 | 卡片占满页面轨道；同页及跨页两侧边界一致；内部区块不得反向撑宽卡片 | 连续卡片仍两侧齐平，内边距缩至 12px，动作留在所属卡片 |
| 摘要、说明、表单与字段组 | 摘要和说明可在卡片内部限制阅读行宽；表单网格最多 712px，控件最多 520px；字段组与控件列对齐 | 表单折为单列；标签、控件、帮助、错误和操作共用左边界 |
| 选择与排序行、列表行 | 行占满所属 section，名称可换行，状态和操作可换行但不脱离本行；完整原文可读或可复制 | 行内操作换行，名称和按钮互不遮挡，不靠截断隐藏全文 |
| 表格与行操作 | 表格位于 `.table-wrap` 一类局部滚动容器；表格可保留可读的列宽，但不能决定卡片或页面宽度 | 只允许表格区域横向滚动；卡片外边界、页面主操作保持可见 |
| 详情与技术披露 | 详情一级卡片占满轨道；原始配置、长 ID、代码、JSON 和 `pre` 在内部换行或局部滚动，摘要在其前 | 原文仍可选择、读取或复制，不造成整页横向滚动 |
| 反馈、进度与操作区 | 字段反馈跟随控件列；表单结果邻近提交区；section 错误留在所属卡片；进度留在触发它的表单或 Operation 区 | 消息和操作可换行，不因状态切换新建窄卡片或挡住恢复入口 |
| 确认及后续浮层 | 当前浏览器原生确认框由浏览器排版，不作为 CSS 可测量的卡片；新对话框、浮层或侧栏需先定义自身宽度、焦点和窄屏边界 | 新容器不得推宽页面或改变原页面轨道；关闭后焦点和上下文仍可找回 |

新增容器时，先说明它属于哪个层级、依附哪个对象、外部宽度来自页面轨道还是内部限制，以及长内容、焦点与 360px 的处理。不得按路由任意创建第三种页面宽度。

## 控件与状态

- **导航**：未选项为中性文字；当前页用浅蓝底与亮蓝文字，并保留 `aria-current`。悬停和焦点可辨识，但不能比当前页更醒目。
- **按钮**：主要动作亮蓝底白字；次要动作白底、中性边框与蓝色文字；危险动作使用语义红色。禁用时仍可读，不呈现为已执行成功。按钮如何排列见[产品语言](product-language.md#按钮位置与主次)。
- **输入**：白底、可见边框、清楚标签。焦点使用至少 2px 蓝色轮廓及适当偏移；错误同时有文字原因。复选框与标签保持同一行或紧邻。
- **反馈**：加载、空、成功、警告和失败分别有清楚文字与适度背景。反馈与触发动作保持邻近，错误不会被通用信息样式冲淡。
- **表格与技术文本**：表格在自己的容器中横向滚动；长名称、Operation ID 与 `pre` 在本区域换行或滚动，不拉宽整页。ID 可以选择和复制。

普通文字与背景的对比度至少 4.5:1，大字至少 3:1。白字亮蓝按钮、辅助文字、表单边界和焦点轮廓都要在实际页面检查。键盘焦点不能只靠底色变化表示。

## 响应式

在 360px 宽屏，页面本身不横向滚动；顶栏导航可换行，操作组可换行，表单保持单列，section 减少内边距。宽表格仅在表格容器滚动，不能遮挡提交、重试或取消按钮。浏览器放大后也以主要动作可见可达为准。

## 正反例

| 采用 | 避免 |
| --- | --- |
| 冷白顶栏 + 一条细边界 | 深蓝色大面积顶栏 |
| 白色 section + 紧凑内容行 | 列表里每行套一张带阴影的卡片 |
| 当前导航、焦点和主要操作使用统一亮蓝 | 多个蓝紫渐变按钮抢夺注意力 |
| 错误有文字、语义色和下一步 | 只用红色标记而不解释 |
| 标签列固定；控件、帮助、错误和保存按钮共用控件列 | 标题、字段与按钮各用不同左边界 |
| 跨路由标题和一级卡片共享 1100px 轨道，设置字段留在卡片内部网格 | Runtime 只有 760px，切到 Status 时标题和卡片突然变宽 |
| 登录卡片在统一外层轨道内居中，内层最多 420px | 将登录的窄卡片宽度复用到管理设置页 |
| 技术文本在卡片内换行或局部滚动，完整内容可访问 | 长名称撑宽单张卡片或遮挡按钮 |
| 列表、表格、字段组、详情和反馈各在所属卡片内控制溢出 | 为加载或错误状态另建宽度不同的一级卡片 |
| 360px 下连续卡片两侧齐平，字段折为单列 | 仅检查无整页滚动，忽略卡片边界与行操作 |

## 后续 UI 变更检查

新建或调整浏览器 UI 时逐项核对：

1. 页面、顶栏、section、控件是否使用上述语义令牌，而非散落的品牌硬编码色？
2. 字阶、间距、边框和圆角是否维持紧凑且可扫描的层级？是否避免默认阴影和卡片套卡片？
3. 当前导航、键盘焦点、主要/次要/危险动作及禁用状态是否可辨？对比度是否达标？
4. 360px 宽屏、长文本、表格、文件选择和主要动作是否可用且无整页溢出？
5. 是否同时按[产品语言](product-language.md)核对页面顺序、按钮位置和文案？
6. 所有已登录路由及详情是否共用最大 1100px 轨道？跨路由标题、说明和一级卡片在相同视口下的左、右边界是否都一致？
7. 桌面管理表单的标签、控件、帮助、错误、字段组和按钮是否按 176px／16px／520px 内部网格对齐，而不改变外部卡片宽度？
8. 登录是否在同一外层轨道内居中，且仅其内层为最大 420px 的单列？360px 管理表单是否折为同一左边界的单列？
9. 顶栏、页面、一级 section、摘要、表单、字段组、选择行、列表、表格、详情、技术披露、反馈和操作区是否逐类遵守上表？长内容是否局部换行或滚动，且不遮挡对应动作？
10. 加载、空、错误、进度和结果未知时，一级卡片的边界是否仍稳定？新增浮层类容器是否事先定义宽度归属、焦点和窄屏规则？

无法沿用某条规则时，在对应 OpenSpec 变更中写明“UI 语言例外”、偏离的规则、理由和替代方案；其余规则继续适用。当前实现可通过浏览器计算样式、键盘操作、360px 检查和代表性截图核对。
