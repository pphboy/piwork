# web-onboarding Specification

## Purpose

提供统一 Piwork 服务端的首次网页配置流程，使安装者无需预设环境变量即可安全创建首管理员、保存模型及 CoreRuntime，并在本机或仅凭服务器 IP 的远程浏览器中观察真实准备状态、恢复中断配置，最终进入完整工作台。

## Requirements

### Requirement: 通过普通网页入口创建首管理员

**Identifier:** ONBOARD-001

空安装 SHALL 在打开服务器普通地址或 `/setup` 时直接提供 Create admin，不要求终端链接、设置证明、本机浏览器授权或额外 Access 检查。来源合法的浏览器 SHALL 自动获得提交所需的普通会话/CSRF；创建请求仍 MUST 校验 Host/Origin、CSRF 和合法账号密码，密码确认遵守 ONBOARD-005。页面不得包含 Open your setup link、Check setup access 或取得/轮换设置链接的步骤。

所有网页、env 和 operator 首管理员创建 SHALL 共享“持久用户集合为空”的原子约束，并发最多一个成功。首个成功提交取得管理员身份，随后关闭首次创建入口并进入普通登录；创建本身不建立管理员登录。账号禁用、密码变更或 runtime 缺失不得重新开放首次创建，不得覆盖已有用户或生成默认密码。

新浏览器、刷新、清 Cookie、服务器重启和普通会话失效后 SHALL 按当前持久用户集合决定创建或登录；必要会话自动建立，不能要求重新授权。旧 `#setup=` 链接 SHALL 移除或忽略其证明后按普通入口处理，不兑换证明或执行写入。创建响应未知时 SHALL 先只读核对是否已初始化：已初始化进入登录，仍为空则保留显式创建方向，不能自动重放或返回设置授权页。

#### Scenario: 无环境变量首次创建
- **WHEN** 安装者启动空安装，在本机或远程浏览器直接打开服务器 IP 并提交合法账号及两次一致密码
- **THEN** 创建一个持久管理员并关闭首次创建入口，随后可正常登录；不要求 CLI、终端链接、预设账号或模型 env

#### Scenario: 普通来源与非法来源
- **WHEN** 来源合法的新浏览器直接打开创建页，或请求使用错误 Host/Origin、缺失或错误 CSRF
- **THEN** 前者自动取得普通提交上下文并可创建，后者被拒绝且没有账号变化；错误不得要求取得设置链接

#### Scenario: 并发创建和后续禁用
- **WHEN** 两个网页或网页与 env/operator 同时初始化，或已有安装后来失去启用管理员
- **THEN** 首次事务至多一个成功，已有用户不被覆盖，后续状态不重开公开 bootstrap

#### Scenario: 浏览器状态丢失和旧链接
- **WHEN** 用户刷新、清 Cookie、换浏览器、重启服务器，或打开过期/已使用的旧设置链接
- **THEN** 空安装直接创建，已初始化安装进入普通登录或已登录页面，不出现设置链接校验或 Access 阶段

#### Scenario: 创建结果未知
- **WHEN** 创建响应丢失，随后状态读取确认已有用户或仍为空
- **THEN** 分别提供正常登录或用户显式重试创建；读取失败显示读取恢复，不自动重放创建、不转入授权页

### Requirement: 在管理员会话中完成模型与 Runtime 引导

**Identifier:** ONBOARD-002

统一应用登录后的 CoreSetup SHALL 作为 Admin 内的 `Quick setup` 页面提供，规范路径为 `/admin/setup`，从 Overview 提供可见入口。页面 SHALL 使用管理区导航，仅呈现模型与准备任务；Create admin 和普通 Sign in 保留独立入口，不在已登录快速配置中重复要求。Runtime 和 AI models 的完整管理入口 SHALL 保留，不为 Quick setup 再建立一套模型或 Runtime 配置。

管理员 SHALL 在引导中查看 Docker 状态。首次空配置的新增模型表单 SHALL 预填 Model ID `deepseek-flash`、API type `anthropic-messages`、Base URL `https://api.deepseek.com/anthropic`，主区域只展开 API Key；Model ID、协议、地址和可选显示名 SHALL 收入默认折叠且可编辑的高级设置。用户可以保留默认只填 Key，也可以展开填写完整合法模型，再选择性 Test；随后由服务端使用随当前版本内嵌的发行 Agent 引用保存 CoreRuntime。Agent 镜像是发行固定值，MUST NOT 提供手填、选择或高级覆盖入口；与 Runtime 管理页遵守 SUI-CFG-002 的同一约束。名称可选，Test 失败不禁止合法保存，不要求创建 Provider、能力模板或重复输入 Key。真实模型 Test SHALL 由用户显式触发，首次启动和保存不得隐式发送模型请求。

模型阶段 SHALL 根据真实目录提供添加或选择：空目录直接显示新增表单；存在模型时允许选择已有项或明确切换添加，不能同时要求填写新增表单与选择旧条目。停用、无 Key 等不可用项保留原因，不把读取失败当作空目录。当前任务 SHALL 只有一个主动作 `Save and continue`，新模型以该次明确意图顺序完成模型保存和 Runtime 绑定；选择已有可用项时只保存 Runtime，不重新创建或索要已有 Key。显式 Test 与保存分别表达，其字段校验、结果与过期判断和 Admin 模型管理保持一致。

模型保存与 runtime 绑定 SHALL 分别呈现已确认事实；后一步失败不能把已保存模型显示为失败或自动重复创建。已确认模型引用 SHALL 保留，用户恢复时只继续未完成绑定；任一步写入结果未知时先只读核对，不自动重放修改或根据模型名称猜测唯一引用。只能确认唯一原目标时恢复确认；存在歧义时提供选择/检查方向。仅有效管理员可以写模型/runtime，普通用户看到真实待配置状态。旧持久模型、引用和 Key 可用性 SHALL 可直接复用。

管理员显式打开已配置安装的 Quick setup 时 SHALL 能查看当前模型并选择已有项或新增模型，不能仅因 Runtime 存在就隐藏配置入口。只有显式 Save and continue 才授权变更；选择与已保存模型及当前发行一致时 SHALL 直接读取准备状态，不重复写 Runtime。默认配置的作用范围继续是后续新 Work。

上述默认值 SHALL 只用于首次空配置的新建草稿，不覆盖已有模型、已保存 Runtime、自定义选择或用户编辑；目录读取失败不能视为空目录。预填默认与读回值 SHALL 作为表单基线，本身不构成未保存修改；用户修改才标记 dirty，同页回读/轮询不覆盖正在编辑的草稿或安全内存中的 Key，敏感清理仍按原会话及提交规则。高级字段校验失败 SHALL 先展开该区域再定位相应字段，不因折叠绕过原完整模型校验。

#### Scenario: 一个引导完成首次配置
- **WHEN** 管理员填写合法模型连接并选择 Save and continue
- **THEN** 在 Admin 的 Quick setup 中以同一次明确意图依次确认模型和引用式 runtime，发行 Agent 自动取得，随后进入准备阶段；无额外 Save runtime、镜像输入、Provider/模板或模型 env 步骤，不预建 Work

#### Scenario: 发行 Agent 不可取得
- **WHEN** 同版默认 Agent 拉取失败或内置发行引用缺失/无效
- **THEN** 显示真实准备状态及重试或发行修复方向，已保存模型保持，不要求用户填写替代镜像、不新增高级覆盖

#### Scenario: Test 失败但配置有效
- **WHEN** 用户显式 Test 得到目标认证或网络失败，随后选择保存
- **THEN** 检查失败与保存事实独立，允许合法配置保存，Key 不回填或记录，管理员会话不因供应商错误失效

#### Scenario: 模型已保存而 runtime 未确认
- **WHEN** 模型保存成功，但 runtime 保存失败或响应丢失
- **THEN** 保留模型引用并分别展示保存与绑定事实，未知时先只读核对；用户恢复只继续未完成绑定，不重新创建模型或隐式重发未知修改

#### Scenario: 选择已有模型
- **WHEN** 安装已有启用且有凭据的模型，管理员选择它并继续
- **THEN** 只提交原模型引用的 Runtime 绑定，不显示必填新增模型字段或要求重输 Key

#### Scenario: 已配置安装使用快速配置
- **WHEN** 管理员从 Overview 显式进入 Quick setup
- **THEN** 当前模型可见且可以选择或新增后显式保存，不重新创建管理员，不因打开页面自动写配置；未改变模型与发行值时只进入准备观察

#### Scenario: 双击继续和过期 Test
- **WHEN** 保存仍在进行时再次提交，或 Test 完成后修改模型连接字段
- **THEN** 保存最多一条在途执行链；旧 Test 被标明不再代表当前草稿，查看结果不重新外发，不因修改自动 Test

#### Scenario: 仅输入Key使用首次默认
- **WHEN** 首次空配置的管理员打开新增模型表单，保持预填值并输入合法 Key 后继续
- **THEN** 未编辑时没有 dirty 提示，主区域只突出 Key；保存提交 deepseek-flash、anthropic-messages 和指定 Anthropic 地址，不自动 Test，后续沿原模型保存与 Runtime 绑定规则推进

#### Scenario: 已有配置与后台回读
- **WHEN** 安装已有自定义模型或管理员已修改高级字段/Key，此时状态回读完成
- **THEN** 保存配置和草稿不被预设默认覆盖；只确认属于当前基线/提交的事实，已有 Key 不回显，不误判刚打开即未保存

#### Scenario: 折叠的高级字段有错
- **WHEN** 自定义 Model ID、协议或地址无效而高级设置处于折叠
- **THEN** 自动展开相关字段并聚焦首个错误，未外发时明确没有模型请求；修正后仍可按原契约保存或显式 Test

### Requirement: 引导状态由持久配置及真实准备状态驱动

**Identifier:** ONBOARD-003

引导 SHALL 区分需要创建管理员、需要登录、Docker 不可用、模型/runtime 未配置、配置已保存、依赖准备中、准备失败及可进入工作台。网页在缺少这些运行条件时仍可打开，不能等待完整 Work readiness 才提供引导。保存确认、镜像拉取、基础就绪、完整交付就绪和具体 Work 能力 SHALL 分别表达，不假造进度或把 health 等同于 ready。

CoreSetup SHALL 以管理员创建、普通登录、模型、准备和工作台出口组织顺序任务，不设置浏览器 Access 或设置链接授权阶段，并清楚显示当前/完成/待处理阶段。创建管理员后 SHALL 沿原流程由用户手动正常登录；账号创建不替代登录。登录后 Quick setup SHALL 只展示模型和准备两步，已完成的账号创建不作为待办重现。模型与 Runtime 确认保存后 SHALL 切入准备或可用结果；显式重新配置遵守 ONBOARD-002，不把独立身份表单与配置任务常驻并列。

准备步骤仅在真实依赖正在准备、等待活跃前置任务或服务端明确安排自动重试时 SHALL 使用 `Preparing Piwork…` 等明确的进行中文案，在主状态的固定槽显示 UIL-PENDING-001 的一组三点、当前准备对象及“请稍候，依赖准备完成后即可进入 Piwork；页面会自动更新”的英文说明。六项技术明细 SHALL 默认折叠并可按需查看；发生明确失败时相关原因、修复方向及查看该项的入口必须可见，不要求逐项寻找；折叠不减少检查，也不为六个明细叠加抢眼等待动画。明确失败、读取中断/未知、缺配置或需要用户操作时 SHALL 停止相应三点，显示真实静态状态和修复/只读恢复方向，不继续宣称仅需等待。组件状态 SHALL 区分等待前置依赖、正在准备、重试、明确失败和 Ready；原始错误码不能替代可理解的原因与下一步。首次资源准备可能需要下载这一事实可以说明，但没有真实数据时 MUST NOT 展示百分比、下载速度或预计完成时间，也不能只以旋转图标或变灰按钮表达等待。

只有当前有效快照的 `status.ready` 和 `preparation.ready` 均为 true，且 docker、agent、packageHelper、defaultContext、fileHelper、snapshotHelper 六项均明确为 ready、没有当前读取失败时，准备页 SHALL 显示 `Piwork is ready`、完成准备步骤并启用完成区主要出口 `Open workbench`。仅基础 Work ready 而任何 helper 尚未完成时 SHALL 继续说明正在等待剩余依赖，完成出口保持不可激活且附近可读到原因；缺少准备状态不视为全部 Ready。就绪后 SHALL 保留手动进入，并仅在本次主动首设导航意图仍有效时单次自动进入工作台：意图由当前管理员在尚未配置 Runtime 的首设流程中直接选择 Save and continue 建立，且该次模型/Runtime 保存已确认，当前有效回读匹配原已确认配置，页面、身份和草稿未被后续操作替换。普通背景状态更新、已配置安装主动管理、直接打开已 Ready 页面及“保存后前往另一目的地” SHALL 不建立自动进入意图；用户最新明确目的地优先。刷新、关闭、回退、重新挂载、离开、身份切换、新编辑或新选择 SHALL 失效该内存意图，不跨恢复持久保存。该标记 SHALL 仅在现有 Quick setup 中复用 view/identity/readGeneration 及已确认配置归属，不引入全局导航框架或新的后端代次字段。读取中断或保存未知时不自动导航，已接受准备可按既有规则继续；再次进入只恢复持久步骤与手动出口。该完成条件只约束本准备页的完成出口，Admin 顶栏的 Workbench 全局导航、Core 基础 Work 准入、局部能力降级和已有安装的工作台访问规则保持。

准备页底部 MUST NOT 显示 `Change model` 或 `Review Runtime in Admin`。Admin 壳的管理导航、手动 `Read current state` 和按需只读诊断 SHALL 保留，管理员仍可离开修复配置并返回；页面不重复嵌套一套 CoreSetup 顶栏。重试中 SHALL 说明对应依赖、可理解的原因及服务端报告的下次重试等待；明确失败 SHALL 给出相应修复方向，不继续声称仅需等待或所有失败都会自动重试。读取中断 SHALL 保留并标明最后确认状态及恢复读取入口，不将旧快照冒充新确认或将读取失败视为 Ready。

关闭/刷新页面或重启服务器后 SHALL 读回已确认的持久状态并继续缺失步骤；不依赖浏览器完成标记，不保存密码/Key 草稿。用户可以离开等待页面，后台准备按既有重试/取消规则执行，不自动创建 Work 或提交 Run。背景读取 SHALL 只更新所属状态，不重建正在编辑的表单、抢焦点或覆盖非敏感草稿；页面/身份切换后的旧响应不得覆盖当前视图或释放新写锁。普通会话/CSRF 需要更新时 SHALL 自动恢复提交上下文；账号失效回到普通登录。网络、模型、Docker 或发行元数据失败显示所属读取/配置恢复，任何错误均不得引导重新取得设置链接或本机浏览器授权，也不自动重放修改。

#### Scenario: 缺模型或 Docker 仍可打开网页
- **WHEN** 空安装启动，或已保存 runtime 但 Engine 不可达
- **THEN** 网页和健康检查可用，显示具体缺项/失败及恢复入口；Work 准入仍按真实状态关闭

#### Scenario: 关闭后恢复
- **WHEN** 模型或 runtime 已保存，用户关闭网页或服务器重启后重新登录
- **THEN** 已确认配置保持，页面继续尚未完成阶段，不要求重建账号、重输已有 Key 或重建模型

#### Scenario: 准备失败后恢复
- **WHEN** 镜像拉取暂时失败随后网络恢复，或配置被修正
- **THEN** 当前代次继续准备并更新真实状态，旧代次结果不覆盖新配置，等待不阻塞管理页面

#### Scenario: 后台状态更新不打断输入
- **WHEN** 用户正在填写模型表单，后台准备或状态读取返回
- **THEN** 输入、焦点、选区与阅读位置保持，状态在所属区域更新，不能清空 Key 或把尚未保存表单当作完成

#### Scenario: 真实准备和工作台出口
- **WHEN** Runtime 已确认保存，Docker/Agent 正在准备，随后基础 ready 而某个非必需 helper 尚未 ready
- **THEN** 准备步骤持续显示准备中、当前等待项、请稍候和自动更新说明，完成区 Open workbench 不可激活；没有虚构百分比或提前宣告完成，已保存配置保持

#### Scenario: 全部依赖准备完成后进入
- **WHEN** 本次直接 Save and continue 发起的首次配置已可靠保存，当前有效回读匹配原配置且基础 ready、全部六项交付依赖 Ready，自动进入意图仍有效
- **THEN** 准备步骤完成、三点停止，单次进入真实工作台并保留手动出口回退；不自动创建 Work 或提交 Run，不为补满动效周期延迟完成

#### Scenario: 依赖重试与明确失败
- **WHEN** 镜像依赖处于 retrying 并报告剩余等待，或依赖明确 failed
- **THEN** 前者展示原因和下次自动重试等待，后者提供修复方向而不继续要求无限等待；两者均保留已保存配置，未全部 Ready 的完成出口不可激活

#### Scenario: 准备状态读取中断或缺失
- **WHEN** 已有准备快照后读取失败，或新响应没有可确认的完整准备状态
- **THEN** 页面区分最后确认状态和当前未确认状态并提供只读恢复，不能因读取失败、缺少组件或基础 ready 就宣告全部 Ready 或启用未确认的完成出口

#### Scenario: 准备页动作聚焦于完成目标
- **WHEN** 管理员查看准备中或已全部 Ready 的 Quick setup 准备步骤
- **THEN** 底部没有 Change model 与 Review Runtime in Admin，仍能手动读取状态、展开诊断或通过管理导航修复配置，返回时继续已确认步骤

#### Scenario: 离开后旧响应返回
- **WHEN** 旧读取/写入正在等待，用户切换页面或身份后再次进入
- **THEN** 旧回调不覆盖新视图、清理新输入、释放新动作锁或执行已失效的离开导航；保存后准备读取迟到时，也不得用旧 Workbench/管理目标替换用户最新路线。已接受的服务端准备继续遵守原生命周期

#### Scenario: 非主动首设的Ready不抢导航
- **WHEN** 管理员主动管理已有配置、初读已 Ready 页面、从刷新/前进后退恢复，或仅后台读取变 Ready
- **THEN** 保留完成状态和手动 Open workbench，不建立或恢复自动导航，不以最短路径为由抢走用户当前任务

#### Scenario: 保存后离开与晚到Ready
- **WHEN** 管理员选择保存草稿后前往 Runtime/其他管理页，或首设提交后编辑/切换身份/离开，而旧准备读取随后 Ready
- **THEN** 最新显式目的地和新视图保持，旧自动意图不能导航、清空新输入或释放新锁；原持久准备仍按既有生命周期继续

#### Scenario: 模型阶段入口收敛与自动安全回读
- **WHEN** 管理员停留在 Quick setup 的模型阶段
- **THEN** 该页 MUST NOT 常驻 Read current state、Manage AI models 或 Runtime diagnostics；准备页及完整管理入口不受影响。目录读取失败或保存结果未知时 SHALL 由现有自动更新执行完整只读核对，不自动重发模型/Runtime/Test，不根据旧状态自动导航

#### Scenario: 无法确认的保存仍有安全出口
- **WHEN** 完整回读仍未找到匹配原模型的记录，或未确认原 Runtime 写入
- **THEN** SHALL 保持表单、Test与继续保存的未知结果锁及一条可理解警告，仅该未解决状态提供 Review saved models 检查出口；普通错误或正常模型阶段不显示该链接；后台零匹配回读保留当前 DOM、焦点与展开，确认目标后才解除对应锁；若多个新增模型均与提交公开身份匹配，沿原契约转为显式选择，不猜测引用、不自动绑定或进入准备

#### Scenario: 读取错误不会覆盖写入事实
- **WHEN** 同页自动读取失败后成功，或未解决保存与读取错误同时存在
- **THEN** SHALL 只清除本次读取错误，不保留陈旧读失败、不清除明确保存拒绝或未知写入警告；未知提示不重复，锁与敏感清理仍按原规则

### Requirement: 完成引导后保留后续配置入口

**Identifier:** ONBOARD-004

首次配置在 ONBOARD-003 的全部依赖 Ready 条件满足后 SHALL 提供进入真实工作台的明确动作，并保留管理员重新查看/修改模型、Runtime 和默认 Work 的入口。CoreSetup 的登录后入口 SHALL 统一到 `/admin/setup`，从 Overview 的 Quick setup、托管 Desktop 的 Quick setup 快捷入口及旧 `/setup` 访问均能进入对应任务。已有 Admin Runtime、AI models、默认 Work 和管理深链接 SHALL 保留，Quick setup 属于 Overview 下的快捷配置，不重新排列顶层工作区。

`/setup` SHALL 保留空安装直接创建管理员的入口，不要求设置链接或浏览器 Access；已初始化但未登录时进入普通 Sign in，需要配置的管理员登录后继续 Admin Quick setup。已登录管理员的旧 `/setup` 链接 SHALL 兼容进入 `/admin/setup`，不再维护第二份已登录配置页；普通用户 SHALL 保留真实待配置/工作台方向，不能因兼容跳转获得 Admin 权限。Quick setup 的直接打开、刷新和前进后退 SHALL 保留正确管理上下文，并按持久事实恢复；任何路由或完成标记都不能替代当前 readiness。

后续修改通过 Quick setup 或完整管理入口完成，不要求在准备页底部恢复已移除的两个动作。已有安装的普通登录继续遵守现行工作台/故障恢复规则，不因 Quick setup 的完整准备条件新增全局登录门禁。编辑草稿离开到其他管理页或 Workbench 时 SHALL 按现有保存/放弃/继续编辑规则处理，已保存模型不得因此丢失；导航、刷新和回退不触发隐式写入。

全局默认变化只影响后续新 Work；已有 Work 的独立配置、运行身份、历史与 desired/active 语义保持。首管理员 env 只影响空安装，不能作为持续管理账号或模型的来源。CoreRuntime 读取如实保留已保存镜像，显式保存采用当前发行固定引用；普通读取、导航或启动不自动升级已有 Runtime 或 Work。

#### Scenario: 重启进入已有安装
- **WHEN** 已初始化安装再次启动
- **THEN** 浏览器登录后进入对应工作台或实际故障恢复，不重新执行首次创建或重置模型

#### Scenario: 修改默认不改变已有 Work
- **WHEN** 管理员在后续设置中更改默认模型，或服务端升级后显式保存 runtime 使用新的内置 Agent 引用
- **THEN** 新 Work 使用已保存的新默认，已有 Work 保持原配置且不自动 Apply、重启或切换模型；仅启动或读取不会自动改写持久配置，也不出现镜像手填入口

#### Scenario: 管理配置后返回
- **WHEN** 管理员从 CoreSetup 查看或修正 Admin 模型配置，再返回引导
- **THEN** 读回已确认模型并继续原配置目标，有未保存内容时先处理，不要求重建模型或反复填写 Key

#### Scenario: 首次身份入口与管理内配置衔接
- **WHEN** 安装者通过服务器普通地址完成 Create admin，并以该管理员普通登录且 Runtime 尚未配置
- **THEN** 在 Admin 的 Quick setup 中继续模型与准备两步，管理导航可用，不再出现要求创建管理员的表单或嵌套顶栏

#### Scenario: 旧入口和直接管理深链接
- **WHEN** 管理员打开旧 /setup、直接打开 /admin/setup，或刷新及前进后退
- **THEN** 使用同一受保护 Quick setup 入口并恢复正确任务和已确认状态；旧 Runtime 与 AI models 深链接保持可用，不复制模型或重发保存

#### Scenario: 普通用户访问快速配置
- **WHEN** 普通用户打开 /admin/setup 或旧 /setup
- **THEN** 前者遵守管理权限拒绝，后者仅显示其真实待配置/工作台方向，不开放配置表单或改变身份

### Requirement: 创建首管理员时确认两次密码

**Identifier:** ONBOARD-005

Create admin SHALL 展示有独立标签的 `Password` 和 `Confirm password`，均使用密码输入并允许粘贴、密码管理器和键盘操作。密码 SHALL 满足既有至少 12 字符及服务端合法性要求，确认密码 SHALL 与密码原文一致，不自动 trim、修改或补齐。确认框失焦或提交时 SHALL 校验一致性；初始未操作状态不得提前显示不匹配错误。任一密码变化后 SHALL 重新核对已触发的确认错误，不能沿用过期校验结果。

不一致、缺失或长度无效时 SHALL 不发送创建请求，在相应字段附近显示英文修正提示；提交校验失败 SHALL 聚焦首个无效字段。有效提交只发送既有账号和一个密码字段，不向 API 增加确认密码或将其作为第二认证因素。重复点击/Enter SHALL 最多一个在途创建请求。密码及确认值不得进入 URL、Web Storage、日志或持久草稿；请求失败、成功或身份离开后的敏感清理沿用现有规则，账号可保留。普通 Sign in 和 operator/env bootstrap SHALL 保留既有输入契约。

#### Scenario: 两次密码不一致
- **WHEN** 安装者填写两个不同密码后使确认框失焦或尝试创建
- **THEN** 确认框附近显示不一致提示，提交时聚焦错误字段，创建请求数为零；可直接修正当前输入

#### Scenario: 密码缺失或长度不足
- **WHEN** 密码不足 12 字符、确认值为空，或两项均未填就提交
- **THEN** 页面指出首个无效字段并阻止创建，不以提交按钮变灰作为唯一说明

#### Scenario: 一致后再次修改密码
- **WHEN** 两项曾一致，安装者随后修改第一项并提交
- **THEN** 使用最新两项重新校验，不根据旧的一致状态创建账号

#### Scenario: 合法创建和重复点击
- **WHEN** 两项合法且一致，安装者连续提交
- **THEN** 只产生一个带账号和单个密码的创建请求，确认值不外传；成功后按原流程进入普通登录，两项密码均清空

### Requirement: Quick setup 提供 DeepSeek API 获取指引

**Identifier:** ONBOARD-006

Quick setup 的新增模型表单 SHALL 在 API Key 标签正上方提供一处始终可见的英文推荐与获取入口：`We recommend using the DeepSeek API directly.`，下一行显示 `Get your API key at platform.deepseek.com.`，其中 `platform.deepseek.com` SHALL 是指向 `https://platform.deepseek.com` 的真实链接。该指引 SHALL 同时适用于首次空配置和已有安装显式 Add model 的新增模式；选择已有模型、准备阶段及完整 AI models 通用表单不显示该局部指引。高级字段仍可编辑，推荐不得限制用户配置其他合法模型。

说明 SHALL 采用与表单同宽的紧凑浅色提示块，具有细边框、圆角、推荐文字与次级说明的清晰层级；链接 SHALL 使用可辨的链接颜色、文字标识及外链标记，悬停与键盘焦点可见。360px 窄屏与宽屏下文字、域名 SHALL 自然换行，完整可读，无横向溢出、截断或遮挡输入。该内容属于静态帮助，不显示错误、成功、进行中状态或弹窗。

链接 SHALL 在新标签页打开，并明确表达外链行为；鼠标普通点击、键盘激活及浏览器原生修饰键操作 SHALL 保留相应链接语义。打开平台时，原页面地址、模型草稿、API Key、dirty 与高级区展开状态 SHALL 保持，不触发站内离开确认、隐式保存、Test、准备或模型/Runtime 写入。链接目标 MUST NOT 拼接表单字段、秘密、会话数据或跟踪参数；平台页面不得取得原页面的 opener。原站内离开、显式保存、敏感清理和 unknown 保护继续有效。

#### Scenario: 首次配置看到推荐与获取入口
- **WHEN** 管理员进入首次空配置的 Quick setup 新增模型表单
- **THEN** 在 API Key 标签上方看到一次完整的两行指引和正确平台链接；原 DeepSeek 默认值、Key 输入、高级区及 Save and continue 继续可用，页面不会因显示指引发送模型请求

#### Scenario: 已有配置按当前表单模式呈现
- **WHEN** 管理员在已有安装选择 Add model、切回 Choose saved model，或查看准备阶段及完整 AI models 表单
- **THEN** 指引只随 Quick setup 新增模型表单出现；其他模式保持其原内容，不在选择已有模型时要求获取新 Key，也不覆盖任何已有值

#### Scenario: 打开平台保留当前配置草稿
- **WHEN** 管理员填写 Key 或修改高级字段后，用鼠标或键盘打开平台链接
- **THEN** 浏览器以新标签页打开固定的 HTTPS 平台地址，目标不含表单或会话数据且无法访问原页 opener；原标签页地址、输入、dirty 及展开状态保持，没有离开确认或新增模型/Runtime/Test 请求

#### Scenario: 宽窄屏下提示清晰且可操作
- **WHEN** 管理员在宽屏或 360px 窄屏查看指引，并悬停或通过 Tab 聚焦链接
- **THEN** 浅色提示块与表单对齐，推荐与说明层级可辨；域名完整、自然换行，链接的外链标记和焦点可见，输入及原主要动作保持可用，不出现横向溢出或错误/进行中提示

#### Scenario: 后台回读与内部导航保持原保护
- **WHEN** 管理员保持新增模型草稿，后台状态读取返回，或随后选择站内其他页面
- **THEN** 提示不重复插入、不替换当前输入节点或改变焦点；原站内未保存草稿确认、unknown 锁及敏感清理规则继续生效，外链行为不绕过这些站内保护

### Requirement: 登录和首次引导的状态读取可超时恢复

登录及首次引导 SHALL 为首次状态、会话与后续必要状态的单次读取设置十秒上限；读取未确认时 SHALL 显示可理解的状态、立即可用的只读重试及符合当前页面身份的合法导航，而非仅增加等待文字。自动读取恢复 SHALL 有间隔和总次数上限，不依赖一个永远悬挂的读取锁；过期读取不能改变新阶段、身份、导航或输入。

网络恢复与状态读取只能恢复当前未确认的事实，MUST NOT 自动重新提交登录、首管理员创建或其他写操作。创建或登录响应未知时 SHALL 先只读核对初始化状态及真实会话，分别展示已确认结果或尚未确认与显式处理方向；核对仍失败不能假定创建失败或开放重复创建。用户当前非敏感草稿保持；密码和其他敏感内容继续遵守既有身份与敏感清理规则，不进入持久存储。

#### Scenario: 状态或会话首读悬挂
- **WHEN** `/login` 或 `/setup` 的首次状态／会话读取十秒内没有结束
- **THEN** 页面停止无限等待并提供立即可用的重试与合法导航；读取锁不会阻止新的显式重试。

#### Scenario: 自动只读恢复成功
- **WHEN** 首读失败后连接在有限自动重试期间恢复
- **THEN** 按真实初始化和会话状态显示创建、登录或下一步，不重复提交凭据或创建请求。

#### Scenario: 首管理员创建或登录响应丢失
- **WHEN** 创建或登录请求已发送但响应丢失，随后状态读取成功或仍不可用
- **THEN** 只依据初始化与会话回读呈现确认结果；无法确认时保留未知提示和显式检查方向，且不自动重发提交。

#### Scenario: 旧状态读取晚到
- **WHEN** 用户已显式重试、切换阶段或改变身份后旧读取才返回
- **THEN** 旧结果不覆盖新状态、输入或焦点，不解除新读取／写入锁，也不执行过期导航。

#### Scenario: 登录结果回读属于其他账号
- **WHEN** 原账号的登录响应未知，而回读的真实会话属于其他账号，或用户已编辑账号输入但尚未发起新的提交
- **THEN** 不把该会话当作原登录的成功确认，不自动导航或解除原提交锁；保留原账号归属及当前非敏感草稿，提供只读检查和合法的显式退出方向。
