# Design

## Context

共享三点本身尺寸固定，但两端 `action-state.ts` 在按钮锁定后仍可向对象容器 prepend/append 一整块反馈；Desktop 的 `controlMarkup` 另在工作区导航上方插入 Work 进度。`readPlaceholder` 在骨架之外还渲染三点与文案，部分 Console 表单直接用更长的等待文案替换按钮文本。引导页的状态槽在非空时才占高。这些位置分别引发移动、重复反馈或作用域不清。

现行 UIL-PENDING-001、DUL-002 和 DWUI-011/019 已约束真实状态与主体连续性，并将骨架限定为静态；本变更允许低对比渐变并加强进入、退出等待时的几何约束。Service 首次启动四格例外继续适用。

## Goals / Non-Goals

**Goals:**

- 按请求拥有者提供原位等待，不移动用户正在操作的按钮、相邻对象和已有内容。
- 区分首次内容读取、明确操作、后台读取、已接受任务以及传输进度。
- 在不中断对象观察的前提下保留实际阶段、未知结果、只读恢复、焦点与用户输入。

**Non-Goals:**

- 修改业务 API、状态机、权限、远端任务协调，或第三方 Service 页面。
- 引入新的组件框架、全局遮罩、强制等待或虚构进度。

## Decisions

### 等待的拥有者

本变更与 `redesign-in-place-loading` 的重叠需求采用同一合并文本：账号菜单不设 Known operations，原任务 ID 在所属详情按需查看。两个变更保留各自新增场景，同步顺序不改变重叠需求。

`apps/*-webui/src/action-state.ts` 保留去重、冲突、生命周期和结果记录，普通 pending 以触发控件或模块既有状态槽显示，不用默认新增反馈块。已有模块专属反馈优先，避免同一任务双重动效。没有可见触发控件时，在对应对象已有状态位置表达；错误、未知结果和确需操作的恢复入口仍持久可见。短结果反馈沿现行行为，不通过隐藏反馈解除锁。

控件内三点使用固定尺寸槽：图标按钮替换图标；文本按钮将待机内容与三点叠放于相同几何区域，保留动作可访问名称；不在按钮旁追加普通等待文案。`apps/ui-shared/controls.css` 管理共用几何、三点与 reduced-motion，避免各端自行扩展按钮。

Desktop 优先保留实际发起控件，重建后仅在动作身份一致且候选唯一时重新关联；无法确认归属则使用局部回退，不能被其他对象的状态槽抑制。十秒以上等待在原控件附近可见地说明对象、阶段和等待建议，并保留状态播报，不改变既有控件几何。

模块状态槽只有作为发起控件自身或明确标识相同动作记录时才抑制通用投影；共享容器或对话框本身不证明对象相同。无可见控件时的普通等待以不占布局空间的局部浮层回退，原对话框仍在时保留其作用域。慢等待提示跟随滚动和尺寸变化，所属控件或状态消失时清理；Service 日志独立读取也提供十秒说明。

### 首次读取与后台更新

Desktop `app.ts` 和 Console 对应页面在内容首次未知时使用贴合原结构的骨架，提供区域名称和 busy 语义，不额外叠加三点。骨架使用柔和渐变，仅改变明暗；减少动态效果时静态显示。已确认内容保持挂载，显式刷新回到原控件，后台普通轮询静默。入口 HTML 用稳定框架承载初始化，页面真实加载失败时仍有可访问恢复。

### 任务状态与对齐

Delete 首次确认成功时重新建立终态后的读回义务，后续重复观察不重置；较早的空列表若因更新的 Work 读取仍保留原行，或新列表仍包含该 Work，均不能完成列表同步。待同代的新列表实际确认移除后才收敛，并保留原 Operation；较新的生命周期意图不被旧 Delete 绑住。

Desktop Work 标题、列表行与 Service 详情使用既有对象状态/动作区域承载任务阶段；避免在 Work header 与 tabs 间插入普通 pending 区域。阶段从真实操作和观测状态取得，提交、接受、实际运行与未知分开；Operation 原 ID 与详情出口保留。上传/下载可量化进度仍使用真实数据。长状态的完整内容及恢复动作放在原对象详情，窄屏不能横向撑开。

Console 的模型表单、Quick setup、身份引导和通用操作分别保留原表单和进度归属；减少可变长度按钮文案及仅在等待时出现的普通状态行。其独立任务结果区域和危险/失败恢复继续按实际内容显示。

### 验证与交付

在受控延迟的浏览器场景记录空闲、等待、完成时按钮和邻近元素的矩形；检查 Work/Service 控制、文件刷新、列表首读、模型设置及引导，覆盖 1440px/360px、中英文与 reduced motion。另验证长期任务、未知写入、真实失败、并发和既有应用/输入连续性。按浏览器资源构建流程同步 Go 嵌入资源，运行相关测试。

### 源码入口与反馈归属核对

下表记录当前源码入口和本变更要求的归属；已有实现不等于已完成浏览器验收。

| 入口 | 首读、操作、后台读取与任务阶段的归属 |
| --- | --- |
| Desktop Works 与 Work | `app.ts` 的 Works 列表及 `readPlaceholder` 承接无确认数据；刷新回原按钮，Work 控制提交回触发器，接受后的阶段回 Work 状态及 Operation 详情。已有列表刷新保留内容。 |
| Desktop Services | `serviceWorkspace` 在未确认 Service 或入口时局部占位；控制与日志属于对应 Service，已展示 iframe 保留；首次真实 Starting 保留四格例外。 |
| Desktop Files 与 Settings | 文件目录、文件内容及配置首读使用所属区域占位，显式读取回路径或刷新控件；上传及其他传输保留真实字节、阶段和恢复，后台读取保留内容与草稿。 |
| Desktop Chat、Session、图片与其他局部读取 | 对话和会话首读使用各自区域占位，刷新回会话控件；Run 属于对应回复，图片、模型、Activity、Core 和 About 的独立读取需分别核对，不能把后台轮询当成新操作。 |
| Console 与 Operation | `action-state.ts` 管理请求及未知锁；`app.ts` 初读壳、原操作控件和 Operation 自身阶段分别承接读取、提交及已接受任务。真实错误与只读恢复保留。 |
| 模型管理 | `model-management.ts` 的读取、保存及启停等属于各自按钮，测试结果属于测试详情；当前 `pendingText` 替换按钮文案，须核对固定几何与名称。 |
| 登录、首设与 Quick setup | `onboarding.ts`、`quick-setup.ts` 将提交关联原按钮，状态槽承接实际阶段、慢等待和错误；普通读取与提交不能重复插入推动表单的等待行。入口资源失败仍需原生恢复。 |

本次受控浏览器矩阵及未测范围记录在 [关联变更验收事实](../2026-10-28-redesign-in-place-loading/acceptance.md)；两项变更复用同一实现和验证，不重复计数。

## Risks / Trade-offs

- [动作来源消失或并发] → 仅在实际所属可见控件显示其等待；任务和未知结果仍能从对象及详情找回，不将其他按钮误标为该任务。
- [覆盖式三点影响读屏或焦点] → 原动作名称与 busy 语义持续保留，装饰点不重复播报，真实冲突禁用规则不变。
- [长操作说明被隐藏] → 对象状态和详情承载真实阶段，慢等待与恢复入口保持可达，不模拟百分比或完成。
- [骨架动态与载入闪烁] → 固定几何，快速响应立即呈现结果，减少动态效果时静态；不把失败或已确认空集合显示为骨架。
