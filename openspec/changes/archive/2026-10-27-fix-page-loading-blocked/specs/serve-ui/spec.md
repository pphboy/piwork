# Spec Delta

## ADDED Requirements

### Requirement: 管理入口首读有界并保留安全导航

管理入口 SHALL 在应用接管后立即提供可见的管理外壳和等待状态；首次管理会话、可达性及当前页面必需读取的单次等待 SHALL 有十秒上限。超时或失败 SHALL 显示未确认事实并立即提供只读重试和当前身份可合法使用的导航，不因等待结果而长期保留静态 Loading。自动读取恢复 SHALL 有间隔和总次数上限；网络错误不等同于已确认的会话失效。

已进入管理页面后的读取恢复 SHALL 局部更新，保留当前路由、未提交草稿、焦点与已确认修改；切换身份或目标后过期读取不得改变新视图或解锁新操作。写入响应未知时 SHALL 优先只读核对原目标，不能自动重发；确认失败时继续说明结果未知。权限未确认时不得展示尚未授权的管理内容或使导航绕过管理权限。

#### Scenario: 管理会话或可达性首读悬挂
- **WHEN** 用户打开管理入口，首次会话或可达性读取十秒内未完成
- **THEN** 页面显示未确认及可执行只读重试，适用的导航可用；不永久停在静态 Loading，也不虚构登录或登出。

#### Scenario: 管理页面局部恢复
- **WHEN** 管理员编辑草稿时读取失败、超时或随后成功
- **THEN** 当前草稿、焦点、已确认保存事实和合法导航保持，读取状态单独更新，不重载页面或重新提交修改。

#### Scenario: 身份和路由发生变化
- **WHEN** 旧管理读取在用户切换路由或身份后返回
- **THEN** 旧结果不覆盖新页面或其输入，不释放新动作的锁，也不触发旧页面导航。

#### Scenario: Core 已提交但转发响应丢失
- **WHEN** 管理写入已经由 Core 提交，而转发连接丢失响应并向浏览器返回 `CORE_UNAVAILABLE`
- **THEN** 保守保留原目标的结果未知和提交锁，只读核对原对象后再提供显式处理方向；禁用按钮与表单提交入口均不能重复发送原写入。
