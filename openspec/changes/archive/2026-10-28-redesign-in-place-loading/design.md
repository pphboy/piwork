# Design

## Context

本变更以 [已 Review 的交互原型](prototype/prototype.html) 为视觉与交互基线；原型中的 Work、Service、上传字节及账户均为合成示例。已发布的 [问题截图和原型](https://piwork-loading-review-20261028-q7.pphgee.chatgpt.site/prototype.html) 可用于对照，实际用户截图及真实 Work ID 不写入仓库。

当前 Desktop 的 `controlMarkup` 将操作状态追加到 Work 行和标题下，`orphanTasks` 在 Works 搜索前插入任务区；`action-state.ts` 可在所属容器创建额外反馈块。首次占位同时输出三点、文字和骨架，固定 24px 三点还会替换更窄的图标。Console 的 `setup-status` 从空到非空时新增高度，模型按钮会改变等待文案宽度。详细问题与用户目标见 `proposal.md`。

用户截图中 `Ready` 与 `succeeded` 并存并不能证明后台已完全收敛：`adapter.ts` 仍分别保护本地记录、生命周期意图和 Work/列表读回。修复要核实为什么这些条件未收敛，而不能仅隐藏 Operation 或删除未知写保护。

## Goals / Non-Goals

**Goals:**

- 让一次动作只有一个主要可见等待位置，普通等待前、中、结束后的既有交互目标保持几何稳定。
- 使首次读取、已有内容刷新、提交、已接受任务及真实传输分别表达，且从用户正在操作的对象找到结果。
- 按原型移除 Chat 中两处指定的常驻信息，保持真实历史读取和 Run 的正确性。

**Non-Goals:**

- 不改变 Core/API、远端任务生命周期、身份权限、危险操作确认或第三方 Service 内部页面。
- 不凭页面显示的 `Ready` 推断所有 Operation 和读回已经确认，不通过隐藏反馈释放写锁或重发修改。
- 不重排既有产品导航或新增全局 Known operations 中心；真实新增消息或新 Work 可正常改变内容高度。

## Decisions

### 1. 等待附着原对象，尺寸在状态切换前后不变

本变更与 `redesign-loading-feedback` 的重叠需求采用同一合并文本，保留两个变更的场景；账号菜单不设 Known operations，原任务 ID 在所属详情按需查看。

`apps/ui-shared/controls.css` 提供尺寸稳定的点状槽、低对比骨架和减少动态效果规则。图标按钮使用与原图标相同的固定区域或叠放层；文字按钮预留相同内容尺寸，不在按钮旁增加普通等待文案。已有列表和内容保持挂载，手动刷新只改变原触发器；首次无确认数据才在对应内容区放置骨架。三点与骨架不为同一等待叠加，真正内容到达即显示。

Desktop 与 Console 的 `action-state.ts` 继续负责动作身份、冲突、未知锁和可访问状态；普通 pending 投影到原控件／所属状态位，而不是默认 `prepend`/`append` 反馈块。单个对象的进度不能使别的冲突按钮看起来是该任务的发起者；失败、未知和需要处理的事实仍保留。

Desktop 优先保留发起控件的实际身份；控件重建后仅在动作身份一致且候选唯一时重新关联。原控件消失且无法确认归属时使用局部回退，不让其他对象的状态槽抑制该任务。超过十秒的等待在原控件附近提供可见、可播报的对象、阶段和等待建议，不改变按钮或相邻内容的几何。

模块状态槽只有作为发起控件自身或明确标识相同动作记录时才抑制通用投影；共享容器或对话框本身不证明对象相同。无可见控件时的普通等待以不占布局空间的局部浮层回退，原对话框仍在时保留其作用域。慢等待提示跟随滚动和尺寸变化，所属控件或状态消失时清理；Service 日志独立读取也提供十秒说明。

### 2. 提交、原操作和对象读回独立收敛

```
Submit --> Accepted --> Running --> Operation terminal
                         |                 |
                         +----> Work / list readback
                                  |        |
                           unconfirmed   confirmed
                                  |        |
                          original check  object status
```

创建请求未返回时，在现有 `+` 控件显示提交等待；仅当真实 Work 出现在列表后，才在该行的状态槽显示操作阶段。Work、Service、Settings 和 Work 头部复用各自的既有状态／动作区域，详情及只读检查从所属对象的现有菜单或面板按需进入，不再默认生成跨行进度块。

原 Operation 成功与 Work 可用是不同事实。只有原结果、对应目标及 Work/列表读回完成，且本地记录与最新生命周期意图没有未决问题，普通成功反馈才收敛为真实 `Ready`／`Stopped` 等状态；更新目标的旧 Operation 保留其原结果，不覆盖新目标。对用户截图中的不收敛，实施时以受控延迟复现 `workControl`、`workSynchronizationPending` 和 `finishWorkSync` 的状态转换，修正实际客户端收敛问题；无法确认时显示准确的未确认事实及原操作恢复，而不是提前清除。

Delete 首次确认成功时重新建立终态后的读回义务，后续重复观察不重置；较早的空列表若因更新的 Work 读取仍保留原行，或新列表仍包含该 Work，均不能完成列表同步。待同代的新列表实际确认移除后才收敛，并保留原 Operation；较新的生命周期意图不被旧 Delete 绑住。

创建或导入尚无 Work 行、删除后行已消失时，不造一条假 Work。原提交／确认流程保留任务身份；关闭或重载后，Works 标题现有操作区使用固定几何的任务入口及非模态按需详情，按创建、导入、删除的真实对象区分多个未决任务。该入口不新增推动搜索与列表的状态行，也不是账号级操作中心。搜索、空列表或读取失败不得隐藏未处理任务；只读检查不重新提交原修改。

### 3. Chat 与历史能力按实际交互表达

`apps/desktop-webui/src/app.ts` 的 Agent 主区不再输出 `historyNotice` 常驻行，也不再以 `unavailableServicesReason` 渲染 Chat 顶部 Alert；Service 的真实状态仍由 Services 上下文承接。只有用户实际遇到历史读取不支持、超限或内容不完整时，在对应历史读取／恢复处说明事实与可执行方向；已读历史、草稿和原 Run 保留，不能假称完整或自动升级镜像。

Run 执行等待在对应助手回复位置用一组三点表达，原取消入口仍可达，真正内容到达后原位显示；不把 `Stop and send` 当作单纯取消。新消息本身进入对话属于真实内容变化，等待反馈不能额外移动输入框、滚动位置或导航。

### 4. 页面场景映射

| 场景 | 主等待位置 |
| --- | --- |
| 全局启动、Works/Work/Service/Files/Chat 首读 | 未知身份时中性启动框架；已知页面在内容区域使用贴合结构的骨架，启动资源失败仍保留原可访问恢复 |
| Works 新建、Work/Service 控制 | 原按钮或对象状态槽；已确认结果取代等待，不在标题与导航间或列表行内追加多行 |
| Settings catalog、登录、Quick setup、模型动作 | 原操作按钮的固定槽；阶段、慢等待和真实错误按所属上下文可达 |
| Files 上传 | 现有文件操作按钮的固定区域表达真实进度；按需展开原文件、数量、字节与阶段，未知总量只显示真实等待；文件菜单仍可用 |
| Pi Requests、Session 与其他已有列表刷新 | 原刷新／选择控件原位等待，列表、选择与阅读位置保持 |

传输进度的环形或点状表现不取代真实字节和确认阶段；弹出详情可由键盘打开，不能仅靠 hover 或颜色。Service 首次启动四格仍遵循现行例外；渐变骨架在 `prefers-reduced-motion` 下静态。入口 HTML、`boot-watchdog.js` 和原生重试在脚本或样式失败时仍有效。

### 5. 责任与验证

`apps/desktop-webui/src/app.ts`、`adapter.ts` 负责 Work/Service/Chat 的状态归属与同步；`action-state.ts` 管理动作记录；`apps/console-webui/src/onboarding.ts`、`quick-setup.ts`、`model-management.ts` 和对应动作反馈负责引导及管理；共享样式与启动资源在 `apps/ui-shared/`。浏览器资源构建后同步 Go 嵌入资源。

受控延迟下比较等待前、中、结束后三个时刻的触发器、目标行、相邻控件与工具栏坐标；以用户两张 Work 截图的 `Ready + succeeded` 情况和 Chat 两处提示为回归场景。覆盖 1440px/360px、中英文、减少动态效果、并发操作、真实失败、未知结果、读回延迟、草稿／焦点／滚动与同一 Service iframe；实际内容新增不计为 Loading 造成的位移。

## Risks / Trade-offs

- [后台仍未确认但主行看起来已完成] → 将已确认事实、真实任务状态和只读恢复分开；不得只因 Operation `succeeded` 或一次 Work `Ready` 就释放同步保护。
- [无对象任务入口收起后难以找回] → 固定所属操作区入口并覆盖关闭、重载、搜索和多个并发任务；保留原 ID 和未决保护。
- [紧凑反馈隐藏真实进度或错误] → 可访问名称、所属状态和按需详情共同表达，已知传输字节、失败原因和安全下一步仍可达。
- [骨架或启动壳遮挡失败] → 真实错误终止等待并呈现恢复；关键资源失败保留不依赖同一脚本的原生出口。

## Migration Plan

不迁移用户数据。实现时先更新共享等待组件与各页面状态投影，再同步构建的 Desktop/Console 资源和相关测试；回退浏览器资源即可恢复旧展示，不改变原操作记录或远端任务。
