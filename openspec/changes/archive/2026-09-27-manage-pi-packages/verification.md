# manage-pi-packages 验证追踪

此表逐项记录 change 中的 requirement 与全部 scenario。每个 scenario 继承所在行的测试集合；这些测试从 API、存储、helper、运行时和产品验收共同覆盖行为，不表示每个 scenario 都有一个同名测试。Docker 验收日志和最终命令结果记录在实施交接中。

四来源与两个安装 scope 的验证由相同的 worker/制品发布路径组合覆盖：`apps/core/src/cli.test.ts` 和 `apps/cli/src/main.test.ts` 分别验证每种来源的 Core、Work 请求；`apps/package-helper/src/main.test.ts` 用本地 npm registry 与 Git 仓库真实解析并冻结来源，也验证本地目录、ZIP 及离线依赖；`scripts/product-acceptance.mjs` 在 Docker 中运行 Core/Work 的本地目录和 ZIP 包并调用真实 Pi SDK 工具；`scripts/work-snapshot-acceptance.mjs` 验证失去原始来源后的跨 Core 搬迁。此矩阵依赖共享的包准备/发布实现，不宣称八种组合各自有一条独立的 Docker 用例。

组合故障由 `packages/pi-package/src/zip.test.ts`（ZIP 限额和越界）、`apps/core/src/packages/worker.test.ts`（准备失败、Core 重启、无重复脚本）、`apps/agentd/src/package-resources.test.ts`（资源冲突）、`apps/core/src/work-management/lifecycle.test.ts`（晚到、忙碌和回滚）、`apps/core/src/work-snapshots/admission.test.ts`（导出竞争）及两条 Docker 验收链共同验证。
