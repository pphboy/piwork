# Proposal

## Why

登录后进入工作台的整页 Loading 将骨架、文字和恢复操作横向挤在左上方，应用接管后又切换为另一种占位，位置与形态缺少连续性。工作台、登录、管理和首次设置入口存在同类启动阶段，需要统一为协调、可恢复的品牌启动画面。

## What Changes

- 所有浏览器入口的整页启动阶段统一使用现有 Piwork Logo、简短提示和三点，按同一中轴在视口中居中；沿用现有配色和中英文，Logo 与文字保持静止。
- 从静态 HTML 到应用接管后的首次会话／初始化读取保持相同布局；真实目标页面可确定后立即交接，不人为延长 Loading。
- 正常加载时隐藏“重新加载／重试”和“返回首页”等恢复操作；资源失败或首次读取超时／失败时，在原品牌区域显示未确认说明及适用恢复入口，保持主要元素位置稳定。
- 保留脚本禁用、关键资源失败及样式不可用时的静态恢复能力，以及现有十秒读取期限、有限自动恢复、身份隔离和路由保护。
- 明确管理入口的阶段边界：身份尚未确认时使用中性品牌启动页；确认管理身份后显示管理外壳，页面数据读取继续使用所属局部占位。
- Work 共用 Header 不显示等待三点，也不插入路由慢读取文字，避免进入 Service、Files、Chat 和设置时推移相邻内容；路由读取、Core 检查及生命周期状态的文字和可访问语义、内容区骨架与失败恢复保留。
- 业务页面内的局部加载、Core 启动恢复与 Service 启动继续遵循各自现行契约。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `ui-language`：增加跨入口居中品牌启动画面、连续接管和恢复操作显隐的共享要求，并约束异常与无脚本回退。
- `serve-ui`：调整管理入口首读要求，明确品牌启动页与已确认管理外壳的交接边界。
- `web-onboarding`：将登录和首次设置的初始状态读取纳入统一品牌画面，保持后续表单、准备阶段及未知提交的恢复语义。

## Impact

- 展示来源：`apps/ui-shared/controls.css`、启动文案与品牌资源；必要的共享展示模块仅接收窄展示输入。
- 静态入口：`apps/desktop-webui/public/index.html`，`apps/console-webui/public/index.html` 和 `setup.html`。
- 应用接管：Desktop `src/app.ts` 的首次会话分支，Console `src/app.ts` 的初始会话占位，`src/onboarding.ts` 的首次状态读取；请求和身份状态继续由原 owner 持有。
- 恢复与资源交付：共享 `boot-watchdog.js`、`prepare-boot.mjs`、两端 `copy-static.mjs`、Go 内嵌资源、两端 UI 输入 hash 及未认证 setup 精确资源公开列表。新增共享模块时同步实际消费者、生成链和必要的合成构建夹具。
- 验证：两端类型检查、相关单元与浏览器回归、真实 Go 入口资源/CSP/Logo 核验、嵌入资源一致性，以及宽窄屏和异常路径视觉验证。
- 不增加运行时依赖，不变更认证／业务 API、生产部署配置或对外发行。
