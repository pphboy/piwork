# Serve UI Users Spec Delta

## Purpose

定义管理员在面板内管理账号的完整交互，使创建、启用、禁用和密码重置可以独立于命令行界面实现与验证，并明确普通用户入口、会话撤销、重复账号和最后一名管理员保护的可见结果。

## ADDED Requirements

### Requirement: 列出与创建管理账号

**Identifier:** SUI-USR-001

用户页 SHALL 从管理员 API 加载账号、用户 ID、角色、启用状态、创建和更新时间，不显示密码材料。列表 SHALL 提供加载、空态、错误重试和手动刷新。创建表单 SHALL 提供账号、初始密码、密码确认和角色选择，角色默认为 `user`，可选择 `admin`。账号 SHALL 满足 `[a-zA-Z0-9][a-zA-Z0-9._:-]{0,127}`，密码为 12 至 1,024 个字符且确认一致；Core 仍独立校验。重复账号 SHALL 显示冲突并保留账号及角色，不自动更新已有用户。

成功 SHALL 显示新用户元数据并清空密码；普通用户的成功提示 SHALL 说明使用 piwork-cli，管理员的成功提示 SHALL 说明可以登录本面板。账号创建后本版不提供改名、删除、修改角色或自助注册。

#### Scenario: 创建默认普通用户
- **WHEN** 管理员使用有效账号及匹配密码提交，未改变默认角色
- **THEN** 创建启用的 user，刷新列表并提示 CLI 入口，不使其获得面板权限

#### Scenario: 创建另一个管理员
- **WHEN** 管理员显式选择 admin 并成功提交
- **THEN** 新账号显示 admin，该账号能使用自己的凭证登录面板

#### Scenario: 无效或重复账号
- **WHEN** 账号格式无效、密码长度/确认不符，或 Core 返回重复账号
- **THEN** 相应字段显示错误，无效本地表单不发送创建请求，Core 冲突不改变已有账号，不回显密码

### Requirement: 安全执行用户状态与凭证操作

**Identifier:** SUI-USR-002

每个用户 SHALL 提供与当前状态对应的启用或禁用动作，以及密码重置表单。禁用和重置 SHALL 在确认中显示目标账号及“撤销全部登录会话”；重置要求新密码及确认。成功 SHALL 刷新用户状态；启用 SHALL 不恢复旧会话。Core 返回 `LAST_ADMINISTRATOR` 时 SHALL 明确说明至少保留一名启用管理员，保持行状态。对象不存在或权限变化 SHALL 显示失败并允许刷新，不以过期快照预测成功。

管理员禁用自身或重置自身密码成功后 SHALL 回到登录页。其他用户的禁用或重置 SHALL 不退出当前管理员。已接受的 Run、Work 服务或 Core 包任务 SHALL 不因该账号管理动作被面板取消。

#### Scenario: 禁用再启用用户
- **WHEN** 管理员确认禁用用户，之后重新启用
- **THEN** 列表反映两次成功变更，用户必须重新登录，原会话不恢复

#### Scenario: 最后一名管理员
- **WHEN** 管理员尝试禁用最后一名启用管理员
- **THEN** 显示最后管理员保护错误，账号保持启用，不显示成功提示

#### Scenario: 重置自己的密码
- **WHEN** 当前管理员确认重置自身密码且 Core 成功
- **THEN** 清空密码输入并退出面板，使用新密码才可重新登录

#### Scenario: 取消或并发删除状态
- **WHEN** 用户取消确认，或提交时 Core 报告对象不可用
- **THEN** 取消不发变更请求；对象不可用显示错误并刷新列表，不修改错误的行
