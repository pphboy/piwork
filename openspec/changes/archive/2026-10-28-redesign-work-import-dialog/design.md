# Design

## Context

现有 Desktop 在同一个 Import 弹窗中完成文件检查和命名，但直接渲染检查对象的 JSON；提交期间已有 transfer 状态，前端没有持续呈现该状态。用户在对话中确认了简化后的弹窗原型，并要求不新增用户必经流程。原型图片未发现于当前工作区，因此实施时应以该对话中的已确认图为视觉参照；本文件明确交互和状态，不能把未取得的图片细节当成新的设计决定。

本变更遵循 desktop-webui 的 DWUI-008、DWUI-013 及 desktop-ui-language 的 Dialog、File Picker、Progress 约定。WorkName 留空、名称冲突、离线 Inspect、提交未知、原 Operation 恢复与显式 Start 语义沿用现行规格。

## Goals / Non-Goals

**Goals:**

- 在既有弹窗内连续呈现文件、名称、真实进度及结果，减少与任务无关的技术信息。
- 覆盖托管 Desktop 和独立 CLI Desktop，并避免焦点、状态刷新和迟到响应破坏输入。

**Non-Goals:**

- 不修改 .work 格式，不引入新的必经步骤或独立 Import List。
- 不改变 Core 导入算法或以本变更承担后端性能目标；性能计划属于 optimize-work-import-performance。

## Decisions

### 一个弹窗承载已有路径

使用现有 Dialog 和文件选择器：选择 .work 后显示上传/检查状态，检查成功后在原位置显示 WorkName，用户显式提交后显示当前提交/导入状态，只有确认成功才显示成功结果。失败保留可执行的错误信息和合法输入；成功保持 stopped，并保留用户显式选择后续操作的能力。原始检查 JSON 完全不渲染，包括隐藏或折叠内容；安全提示和最终名称使用简明文本。

去掉弹窗中的 “Find an original Import task”，不以新的列表或查找步骤替代。已有 Operation 记录、同一身份的恢复与未知结果保护继续工作；不因关闭弹窗重新提交或自动取消已受理任务。

### 焦点和输入

在当前 transfer 首次检查成功、WorkName 控件进入 DOM 后聚焦一次；如果用户已主动把焦点移动到其他控件，不抢回焦点。后续进度渲染通过现有 reconciliation 保持输入值、光标与用户焦点。选择另一包、取消、切换身份或晚到响应只能影响其原 transfer，不能把旧结果或焦点带入新弹窗。

### 只显示可证明的进度

选择文件的实际传输按已有真实数据展示易读的 MB/GB 和已知百分比；检查、内部转交、提交或恢复没有可信分子/分母时使用阶段性等待，不显示伪百分比。当前 transfer 的 transferred 可能仍是首次接收量，不能把它复用成点击后的 Core 转交量。提交请求未返回时可观察同一 transfer 的阶段；受理后观察原 Operation，状态观察中断或结果未知保持原身份并展示可执行的恢复信息。

涉及 apps/desktop-webui/src/app.ts 的弹窗与交互、adapter.ts 的现有 transfer/Operation 观察、样式和中英文文案。优先利用现有状态接口；如缺少真实字节数据则使用不可量化进度，不为百分比编造数据。

## Risks / Trade-offs

- [原型图未在工作区找到] → 以已确认的对话原型核对视觉；此设计只固定已确认的行为，实施时报告视觉参照不可访问的事实。
- [重复渲染抢焦点或晚结果覆盖新选择] → 焦点仅在首次可输入时设置，并按 transfer/会话身份丢弃过期结果。
- [用户把传输完成当作导入完成] → 分别展示真实阶段；以 Operation succeeded 确认成功。
- [关闭或未知响应导致重复导入] → 沿用原 transfer 与 Operation 恢复规则，不自动重发。

## Migration Plan

无需包格式、数据库或用户数据迁移。构建 Desktop 静态资源并同步嵌入宿主程序；回滚 UI 资源即可恢复先前外观，已接受的导入按原 Operation 保持可观察。

## 验证记录

- 2026-10-28：Desktop 类型检查、资源构建通过；导入专项浏览器测试覆盖同一弹窗内的转交阶段和结果、原身份、显式 Start、360px 布局及名称焦点。已查看真实检查/重名弹窗截图；对话中确认的原型图当前无法从工作区取得，因此未能逐像素比对。
- 完整 Desktop 浏览器测试最终以并发 3 执行 1050 项：1049 通过、0 失败、1 跳过。跳过项为需显式设置 `PIWORK_RUN_ENGINE_BROWSER` 的 Engine 初始化场景；本变更的真实 Core 导入另见下条。此前发现的初始化页面窄屏溢出已修复，语言菜单及导入身份断言已适配现行交互；此前高并发中发生的端口竞争和观察时序失败均在最终测试中通过。测试使用隔离 Core，并仅在测试二进制中将 Agent RPC 端口改为动态分配，以避开其他安装使用的 7172 端口。
- 使用最终构建的 CLI 和隔离 Core，浏览器实际导出并上传约 612 MB 包，验证名称聚焦、重名恢复、同一弹窗中的导入状态、导入后 stopped 和显式 Start。名称冲突后不再保留提交中状态；测试结束确认两个测试安装的容器、网络和卷均已清理。此验证不是性能基准，且包含工作区中独立性能变更的当前代码。
- 后续核验修复：检查期间用户主动移动焦点后不再抢占；关闭导入或原 Operation 弹窗停止对应本地观察，重新打开时继续观察原任务；终态关闭后可选择另一包，原任务记录保留。丢失响应后，仅在同一 transfer 通过独立的新读取确认 ready 时解除原提交锁，保留用户显式重试；旧进度或恢复响应不能覆盖新一轮提交。Desktop 类型检查、资源构建及 19 项相关浏览器回归通过；前述全量测试和真实 Core 测试发生在此次修复之前。
