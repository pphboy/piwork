# Proposal

## Why

Chat 中旧的 cancelled 对话被显示在新消息之后，造成新消息被取消、Agent 回复消失的错觉；运行时发送反馈和 Agent 进行中提示的位置也不易理解。用户需要可信的对话顺序，以及紧贴消息的发送和回复状态。

## What Changes

- 按真实 Session/Run 关系合并历史、实时消息和工具活动，修复旧消息及其终态被追加到最新对话末尾的问题；确认取消和异常后已输出正文的保存、恢复行为。
- 用户提交后在对应消息旁展示发送中及结果未知、失败的状态，受理后与真实 Run 接合，保留原提交键核对和草稿安全语义。
- 在所属 Agent 回复处展示进行中状态，使用全局三点动效并放在文字后，状态文字与动效居中对齐；终态及工具活动仍准确对应原 Run。
- Stop and Send 保留原有组合动作语义，按钮改为停止方块图标，提供准确的可见提示及无障碍名称；不改变显式取消授权边界。
- 使用本变更的 `prototype.html` 作为视觉与交互方向，实际行为由规格及验收覆盖。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `desktop-webui`: Chat 消息的顺序、发送状态、Agent 进行中提示和 Stop and Send 图标。
- `agent-conversation`: 取消或异常后的已输出正文保存与恢复，避免历史重读覆盖已知内容。

## Impact

涉及 Desktop Chat 投影、发送和观察协调、界面样式及本地化、Agent 执行和历史读取，以及相应单元与浏览器测试。若现有公开历史契约不足以完整恢复正文，需按现有兼容能力边界评估契约与生成产物。不会修改实际 Work 数据，也不自动部署或发布。
