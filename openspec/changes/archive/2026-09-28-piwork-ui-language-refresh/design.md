# Design

## Context

参见 `proposal.md`。仓库当前只有 `apps/console/public/index.html`、`style.css` 与 `src/browser/app.ts` 构成的浏览器 UI；`apps/console/src/server.ts` 在启动时把 HTML、CSS、JS 读入内存，通过现有 HTTPS 面板进程提供。现有浏览器测试使用 Playwright、临时 Core fixture 和 390px 默认视口，已有一项 360px 溢出检查。功能边界由 `serve-ui*` 规格定义，本变更补充独立的视觉规则与产品交互表达规则。

## Goals / Non-Goals

**Goals:**

- 让两份独立的中文仓库文档分别成为未来浏览器 UI 的视觉和产品表达评审依据，并在当前面板提供可追溯的首个实现。
- 在紧凑密度下为所有管理路由的标题、页面容器、一级卡片、列表和表单建立同一可量测的横向基线；在桌面和 360px 窄屏保持可读、可操作。
- 让每个页面的 Content 清楚说明管理对象、当前事实、作用范围、主要动作和真实结果，且按钮位置和文案遵循跨页面规则。
- 在未收到其他语言要求前，让浏览器 UI 自有文字只使用英文；中文规范文档继续承载设计约束。
- 保留真实 HTTPS 进程预览方式，并提供无敏感数据的可复核截图。

**Non-Goals:**

- 不修改 Core、管理 API、CLI、身份验证、会话、文件上传与 Operation 的行为。
- 不引入 React、组件库、运行时设计系统包、主题切换或新的预览服务。
- 不改动现有七条路由、增设新首页或改动 Core 行为；不为终端 CLI 定义浏览器布局、CSS 配色或英文界面约束，也不要求未来 UI 与当前面板共享同一个构建产物。

## Decisions

### 1. 两份规范分别管理视觉与产品表达

已新增的 `docs/ui-language.md` 只定义视觉令牌、内容容器与表单网格、字阶、密度、组件外观、状态色、响应式与可访问性；已新增的 `docs/product-language.md` 只定义 Content 的信息组成与取舍、页面信息顺序、动作层级和位置、稳定术语、英文 UI 文案、反馈、确认和异步进度。两份中文文档各自有检查清单和可核对的正反例，从仓库 README 与 `docs/serve-console.md` 同时链接。后续新增浏览器 UI 必须同时检查两份文档；偏离时在对应变更中明确是哪套规则、原因与替代方式。

这两个文档是不同问题的依据：前者回答“看起来如何”，后者回答“用户如何理解和操作”。`style.css` 的 `:root` 用语义 CSS 自定义属性实现视觉令牌；`app.ts` 使用语义类名和统一文案模式。保留现有 `specs/ui-language/spec.md` 作为两套要求的共同可验收契约，但不将两份文档合并成一份，避免以后只改颜色时被迫修改产品文案规则。

产品语言参考 GitHub Primer 的[导航](https://primer.style/product/ui-patterns/navigation/)、[保存](https://primer.style/product/ui-patterns/saving/)和[内容](https://primer.style/product/getting-started/foundations/content/)原则，以及 Linear 对[低噪音界面](https://linear.app/now/behind-the-latest-design-refresh)的处理。借鉴的是清晰的作用范围、可预期的操作与信息优先级；具体名称和状态必须按 piwork 的真实契约表达。

### 2. UI 语言的首个令牌集

初版令牌约定如下，文档与 CSS 保持一致：

| 角色 | 值 | 用途 |
| --- | --- | --- |
| `--ui-canvas` | `#F5F8FC` | 页面背景 |
| `--ui-header` | `#F8FBFF` | 顶栏 |
| `--ui-surface` | `#FFFFFF` | section、输入背景 |
| `--ui-border` | `#DCE7F2` | section、分隔线 |
| `--ui-control-border` | `#BAC9D8` | 输入与次要按钮边界 |
| `--ui-text` | `#1B2634` | 正文与标题 |
| `--ui-muted` | `#526477` | 帮助文字与元数据 |
| `--ui-accent` | `#0969DA` | 主要按钮、链接、焦点、选中导航 |
| `--ui-accent-hover` | `#0759BA` | 强调控件悬停 |
| `--ui-accent-soft` | `#EAF3FF` | 选中导航与信息背景 |
| `--ui-danger` / `--ui-warning` | `#B42332` / `#8A5A00` | 错误与警告文字；仅语义用途 |

字阶为正文 14px/1.5、页标题 22px、section 标题 16px、辅助文字 12–13px；间距以 4px 为基础，常用 8/12/16/20px；顶栏目标高度约 56px，内容最大宽度 1100px，section 内边距桌面 16–20px、窄屏 12px，圆角 6–8px，按钮和单行输入最小高度 34px，表格行目标高度 40–44px。无默认投影；只有将来出现浮层时才能局部使用弱阴影。所有尺寸在 360px 和浏览器放大后仍以不遮挡操作为准。普通文字对比度至少 4.5:1，大字至少 3:1；主色按钮的白字、辅助文字和焦点边界在实施时实测。

选择文档加 CSS 变量，是因为当前仅有一个浏览器 UI，运行时共享包会增加构建耦合。若未来出现第二个浏览器 UI，可从文档迁出共享令牌文件；本次先固定语义名称，避免该迁移改变视觉契约。

**统一页面轨道与表单网格**：顶栏内容和 `main` 对全部浏览器路由采用同一个最大 1100px 的内容轨道；已登录路由的页标题、说明和每张同级一级 section 均占满该轨道，左、右边界在路由切换前后保持一致。移除当前基于 `Runtime`、`Default Work` 的 760px 页面宽度选择；`.form-card` 仅标识内部表单样式，不能决定外部卡片宽度。登录保留单任务例外：外层仍是 1100px 页面轨道，标题、说明和表单卡片在其中形成居中的最大 420px 内容列；不把此例外继承给设置页。屏幕宽度小于轨道上限时，页面轨道收缩为视口扣除既有水平内边距的可用宽度，一级卡片继续填满轨道。

除登录外，桌面管理表单仍采用 176px 标签列、16px 列间距及最大 520px 控件列，总内容网格最大 712px；输入、选择器、文本区、文件选择、字数计数、字段帮助、校验错误和提交操作从控件列同一左边界开始，字段组外框和内容亦以控件列为基准。卡片内其他摘要或说明可按阅读需要限制行宽，但不改卡片外边界。卡片剩余空间保持安静的留白，不拉长字段，不追加装饰性侧栏。宽度不足以容纳两列时表单改为单列：标签在控件上方，帮助／错误和操作与控件同宽、同左边界；360px 下无整页溢出。文件选择与复选框保持可用，不借助绝对定位凑齐对齐线。

容器规则按层级复用，不再为每条路由分配一套宽度：

| 容器角色 | 视觉宽度与溢出 | 内容与动作归属 |
| --- | --- | --- |
| 顶栏、页面标题和说明 | 同一 1100px 页面轨道；窄屏同步收缩 | 导航保持当前路由，标题说明管理对象和作用范围 |
| 一级 section：状态、列表、设置、上传、查询、详情 | 占满页面轨道，同页和跨页两侧对齐；状态切换不改变宽度 | 一个明确管理目的，局部刷新靠近标题，结果留在本区 |
| 摘要、表单、字段组、选择及排序行 | 在所属 section 内控制阅读或字段宽度；表单最大 712px，控件最大 520px | 当前事实先于编辑；字段帮助、错误和提交动作对应具体字段或表单 |
| 列表行、表格和行操作 | 行占满所属 section；宽表格只在 `.table-wrap` 滚动 | 名称、状态、操作属于同一对象；空态和读取失败留在列表区 |
| 详情、可展开技术内容和 `pre` | 详情卡片占满轨道；长名称、ID、配置与 JSON 在内部换行或局部滚动 | 摘要和主要动作在前，完整原文与诊断信息在后且可读取或复制 |
| 反馈、上传进度和恢复入口 | 字段反馈跟随控件列，表单结果跟随操作区，section 错误留在本卡片；不得另生窄卡片 | 加载、空、失败、未知和异步阶段各说明可确认事实与下一步 |
| 确认与将来可能的浮层 | 当前原生确认框由浏览器排版，不作为 CSS 卡片；将来新容器需先定义自身宽度及窄屏边界 | 文案写明目标和后果；新容器还需明确焦点、关闭与恢复方式 |

这张矩阵是两份语言文档的共同目录：`docs/ui-language.md` 定义每类容器的几何与溢出，`docs/product-language.md` 定义其对象、事实、动作、状态和恢复。未来出现新容器时按角色扩展矩阵，不按页面名复制任意宽度。浏览器几何测试比较跨路由标题与一级卡片的真实两侧边界，也检查登录例外、表单内网格和技术内容局部溢出。

### 3. 产品语言的页面、按钮与文案规则

`docs/product-language.md` 按「术语 → 页面骨架 → 按钮位置 → 文案模式 → 状态与恢复 → 逐页示例」组织，规则独立于 CSS：

- **Content 骨架**：每页按「管理对象与范围 → 当前可确认事实 → 可修改内容 → 操作 → 结果或恢复」呈现；标题附近一句话交代范围，section 标题只说明区块目的，字段标签只说明输入对象，帮助文字只说明限制、影响或下一步。列表和状态先给可判断的摘要，再给时间、ID、来源或原始配置；技术详情（原始公开配置、Operation JSON、错误码）位于摘要之后，可展开或在次级区域阅读。加载、空、失败、未知均保留对象与范围，但不填假值或重复帮助文字。七条 URL 和权限边界不变。
- **按钮位置**：刷新放在其更新的列表/状态 section 标题附近，复制贴近 ID，返回贴近详情标题。每个独立表单末尾放自己的保存、创建、上传或安装按钮；默认 Work 的多字段编辑只有一个保存入口。列表行操作与行对象相邻，危险动作使用单独的视觉区域或行末风险位置，确认写明目标与后果。窄屏换行后仍保持这种关联，不把按钮挪到全页无关的位置。
- **主次层级**：每个独立表单/section 最多一个视觉主要动作；刷新、复制、取消、返回是次要动作；禁用、移除与重置密码使用语义危险样式和已有确认流程。按钮是否可用仍按原校验、草稿和网络状态判断，视觉样式不改提交规则。
- **英文界面与术语**：未经用户明确要求其他语言，UI 自有文字只用英文，包括页面、导航、字段、按钮、帮助、反馈、确认、浏览器标题和无障碍名称。规范文档继续使用中文。固定导航映射为 `/` = `Status`、`/users` = `Users`、`/runtime` = `Runtime`、`/default-work` = `Default Work`、`/skills` = `Skills`、`/packages` = `Packages`、`/operations` = `Find Operation`；最后一项仅按 ID 查找，不能暗示有任务列表。技术术语稳定使用 `Core`、`Work`、`Skill`、`Package`、`Operation`、`Runtime`、`Default Work`。按钮优先英文动词加对象，如 `Save runtime`，避免孤立的 `Submit` 或 `OK`。用户输入、文件内容、账号／资源名称、ID、错误码和 correlationId 原样保留；它们不受 UI 文案语言限制。
- **英文反馈句式**：先写已确认事实，再写影响和下一步。加载如 `Loading users…`，空态如 `No users yet. Create one below.`，失败如 `Could not load users. Retry.`，结果未知如 `Save result is unknown. Read the current configuration before retrying.`。上传完成、Core 接受、Operation 进行中和终态分别表达；历史状态须标出时间。服务端自然语言 `message` 可能不是英文，因此浏览器不能直接把它当作界面说明；以已知错误码和操作上下文选择英文说明，未知码使用不臆测原因的英文兜底，安全的错误码、字段和 correlationId 保留在辅助诊断信息中。服务端响应及错误码不因翻译改变。

为使产品语言覆盖可实施的细节，文档和面板还要共用以下内容决策；这些规则决定用户看到的信息和动作关系，具体换行与尺寸由 UI 语言规定：

| 情况 | 内容与动作规则 | 验证重点 |
| --- | --- | --- |
| 长名称与 ID | 先呈现对象名称和状态；完整原文可在本行读取或复制；缩略形式不能是唯一入口 | Default Skills、Package 来源及 Operation ID 在桌面和 360px 均可获取全文，行操作仍指向正确对象 |
| 空选择与失效引用 | 空选择明确说没有选中项并给选择入口；已选但失效的项保留名称、顺序和原因，直到管理员处理 | Default Skills 不只显示排序标题；禁用或移除后的引用不从草稿中消失 |
| 重复行操作 | 可见按钮使用简短动词；无障碍名称包含完整对象名和动作方向；危险动作说明实际目标和影响 | 同名开头的多个 Skill 可分别排序，屏幕阅读器能区分按钮 |
| 草稿与提交 | 无更改、已修改、提交中、明确失败、已确认成功和结果未知分开表达；未知结果先读取当前事实 | 不重复提交未知结果，不把局部失败写成全局成功 |
| 错误层级 | 字段错误贴近输入并给修正方式；整区读取／提交错误放在所属 section；错误码、字段名和 correlationId 是辅助诊断 | 服务端非英文 `message` 不充当主说明，诊断串不淹没下一步 |
| 异步与恢复 | 分清文件选取、浏览器上传、Core 接受、Operation 运行和终态；中断后保留 ID、时间与已确认状态 | 可按同一 ID 恢复查询，不暗示自动重提或已完成 |

设置页初次请求要显示对象明确的加载状态；空配置与读取失败分别显示引导或重试。帮助文字只解释限制与影响，不能替代当前状态或错误。Default Work 中从本机选取 `AGENTS.md` 只改变浏览器草稿，须与真正保存结果分开表述。

落到当前页面的确定布局与关键文案如下：

| 页面 | 信息顺序与动作位置 | 必须说清的范围或状态 |
| --- | --- | --- |
| 状态 | 可达性、健康、就绪、checks；刷新位于状态区标题旁，配置入口随缺失项出现 | 健康不等于就绪；断线时当前状态未知，历史值标时间 |
| 用户 | 列表 section 与创建表单 section 分开；行末保留状态/重置操作，创建按钮在表单末尾 | 普通用户使用 CLI；禁用和重置会撤销对应会话 |
| 运行时 | 当前配置摘要在前，编辑表单在后，保存位于表单末尾 | 每次保存需完整 Key；保存成功与运行就绪分开；已有 Work 不变 |
| 默认 Work | 当前公开配置与字段组在前，文件选择紧邻 AGENTS.md 编辑区，统一保存位于表单末尾 | 仅影响以后创建的 Work；选本地文件只是填入草稿，不立即保存 |
| Skills | 列表用紧凑行，上传表单单独成区；详情中的禁用/移除紧邻目标且标风险 | 上传的是浏览器设备的目录；文件发送完成不等于 Core 发布成功 |
| Packages | 列表、安装/更新表单分区；来源字段互斥，主要按钮在表单末尾 | Core 包库与已有 Work 分离；安装接受不等于安装完成 |
| Operation | ID、状态和阶段在前，复制贴近 ID，技术详情在后；无 ID 时查询按钮在表单末尾 | 观察中断保留 ID 和历史状态，按同一 ID 恢复查询 |

文案优化优先在 `app.ts` 的页面提示和 `note` 调用处实施，`index.html` 的 `lang` 与标题须改为英文；浏览器对服务端错误只依赖可确认的代码、字段和操作上下文生成英文说明。现有 `submit` 帮助函数会追加通用成功提示，实施时要避免与更具体的 Core 结果重复，尤其不得把“已接受”或“已保存但未就绪”升级成最终成功。更改可见文案时同步修订依赖精确文本的浏览器测试，不更改服务端错误码或认证语义。

**既有规格冲突**：持久化 `serve-ui` 的 SUI-004 要求默认中文与中文导航名，SUI-002 及用户、运行时、Package 规格还直接引用中文界面文案。本变更新增四份对应 capability 的 delta，完整修订受影响的 requirement，并保留各自认证、状态、上传与恢复行为；其余中文叙述是规范撰写语言，不要求 UI 显示中文。

### 4. 保留原生 DOM 与行为，仅调整可复用页面骨架

把 `style.css` 从单行样式整理为令牌、基础排版、布局、控件、状态与窄屏规则。`index.html` 保持语义性的 header/nav/main；仅在需要时添加容器或类名。`app.ts` 保留 `reset`、`card`、`note`、`action` 等行为入口，将通用 section、页标题/说明、行、状态标签、操作区样式落到少量语义类，不引入客户端路由或模板框架。样式选择器以类为主；避免对所有 `p`、`label`、`button` 的位置作宽泛假设，以免影响文件上传和动态表单。

各页面采用「页标题 → 一个或多个白色 section → section 内标题/描述/内容/操作」的视觉骨架，与上一节的产品信息顺序对应：登录用窄列 section；状态用概要行与 checks 行；用户和 Packages 用紧凑表格；Skills 用分隔列表行；运行时和默认 Work 用对齐的字段组及稳定的保存操作区；Skill/Package 详情与 Operation 将元信息、操作和技术内容分层。原有加载、空、错误、警告、禁用与轮询语义不变，外观与英文文案分别按两份文档统一。破坏性动作继续用语义红色或低强调边界，不占用品牌蓝。

页面宽度由全站统一内容轨道控制；同页和跨页的一级 section 占满该轨道，表单网格与技术内容在卡片内部约束。窄屏时顶栏导航换行，section 内边距降低，操作区允许换行，所有可缩列项目设置最小宽度为 0。表格继续仅在 `.table-wrap` 内横向滚动；长名称、Operation ID 和 `pre` 内容在本区换行或滚动。焦点使用 2px 蓝色轮廓及偏移，不依赖悬停或颜色单独表示状态。

选择对现有 DOM 做小范围语义整理，是为了让当前七个导航页和详情页共享规则，同时保留原测试覆盖的表单、路由、上传与会话流程。备选的完整组件重写会放大功能回归风险，本次不采用。

### 5. 以现有服务和 fixture 完成预览与验收

`docs/serve-console.md` 增加两份语言文档的链接、localhost HTTPS 预览示例、样式或文案修改后重新构建并重启面板的说明，以及 1440px 桌面和 360px 窄屏检查入口。原因是服务在启动时读取构建后的静态文件，浏览器刷新本身不会读取源文件。示例沿用既有 `--core`、`--listen`、`--public-origin`、证书与私钥参数，不提供绕过登录的预览后门。

在现有 `apps/console/browser-tests/console.spec.mjs` 的临时 Core fixture 下增加可重复的视觉和产品表达检查：除令牌、导航、焦点、窄屏与状态区分外，比较所有管理路由之间页标题、说明及一级卡片的左右边界，以及桌面标签列、控件列、帮助／错误文字、字段组和提交按钮的真实几何位置；检查 360px 单列布局、局部滚动与所有主要动作可达。逐页验证导航和 UI 自有文字为英文，并注入长名称、失效 Skill、非英文资源名、文件内容和服务端错误消息，确认完整原文可访问、对象与动作关联清楚、原始数据不改写、界面说明仍为英文。覆盖空选择、初次加载、字段错误、整区错误、草稿、提交中、结果未知和异步恢复；对登录窄列、列表／表格、字段组、技术披露和反馈逐类核对容器矩阵。分别在 1440px 与 360px 捕获登录、状态、用户、运行时、默认 Work、Skills、Packages、Operation 与详情代表性页面截图至被 `.gitignore` 排除的 `test-results/ui-preview/`。截图使用 fixture 数据，不使用真实管理员密码或 API Key。现有功能测试继续负责安全和交互回归；人工用两份文档检查其余页面与异常态。

选择现有 HTTPS 进程与 Playwright fixture，是为了避免第二套面板生命周期、假登录入口或仅为预览增加产品依赖。

## Risks / Trade-offs

- **文档与 CSS 令牌漂移** → 在文档中列出相同语义名和值，浏览器测试核对关键计算样式；后续 UI 变更检查清单要求同步审查文档。
- **产品文案误述 Core 状态或与现有规格冲突** → 以 `serve-ui*` 功能规格和 API 响应为事实边界，逐页用 fixture 覆盖状态转移；只改可见表达，不推断未确认的成功。
- **降低密度后可读性或触控操作受损** → 用 360px、键盘导航、焦点可见性及文字对比度检查作为验收；控件保持至少 34px 高，危险动作仍要求确认。
- **通用 CSS 改动影响动态表单和表格** → 用局部语义类和现有行为测试约束，逐页检查 Skills/Packages 文件选择、默认 Work 复选框与 Operation 长 ID。
- **截图不足以证明真实运行行为** → 截图只证明视觉，仍运行现有浏览器回归并用真实 `piwork-console serve` 手动预览；不把 fixture 截图当作 Core 验证。
- **英文 UI 与旧中文规格冲突** → 使用 `serve-ui` 及相关 capability 的 delta 明确修订可见文案要求，保留七条路由及功能语义，并在归档前同步核对主规格。
- **服务端或用户数据含非英文** → UI 自有说明按错误码和上下文输出英文；用户数据、技术标识保持原文，不通过翻译改变事实。
- **统一宽卡片使设置页右侧留白增加** → 保持最多 712px 的表单内容网格，并用 section 标题、摘要及字段组建立阅读层级；不拉长输入或填充无用途装饰。
- **新增状态反馈或长内容重新撑破容器** → 测试跨路由卡片边界和所属容器的局部换行／滚动，并以两份语言文档的容器矩阵逐类复核。

## Migration Plan

初版两份语言文档、视觉令牌、表单网格、英文界面、同页卡片双侧对齐与预览已经完成。本次后续增量先把跨页统一轨道和容器职责矩阵写入两份文档，再调整面板布局、浏览器几何测试和覆盖全部管理路由的代表性截图。部署继续使用原构建与启动命令；没有数据迁移。若回归需要撤销，回退浏览器静态资源与文档即可，Core 和持久数据不受影响。
