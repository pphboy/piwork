# Design

## Context

动机见 [proposal.md](proposal.md)。当前生产入口与独立 CLI Desktop 共用 `apps/desktop-webui`，浏览器资源构建后嵌入 Go；这次应在共享消息区完成调整，避免两个入口产生不同交互。

现行代码事实：

- `app.ts` 的 `messageSubmissionMarkup` 在用户消息下方铺文字状态，`replyStatusMarkup` 另起“Agent 正在……”行，`executionMarkup` 再铺 Run 状态与详情；发送成功还经 `actions.confirm` 生成 Message accepted 回执。
- `adapter.ts` 已有提交快照的临时用户消息、`chatSubmissions` 原键核对、`cancelRun`、活跃 Run 能力读取及带 `cancelRunId` 的 `send`。明确失败会释放在途意图，消息对象目前只保留提交键、状态、错误及少量输入；没有完整的“重试原快照”模型。
- `models.ts` 的工具投影仅保存工具 ID、名称、状态与结果内容；`chat-projection.ts` 和事件接收路径没有给 UI 保留完整工具输入。不能假定原型的 `outline.md` 路径和参数已由协议提供。
- `expandedActivity`、`chatReading` 和 DOM 协调已支持工具展开、消息锚点、输入节点与 Service iframe 保留。`action-state.ts` 也承担在途、防重复及未知锁，不能只删反馈节点而丢掉协调依据。
- 有效规格仍明确要求用户消息显示发送文字、独立 Agent 状态文案，并要求 Activity 数量和失败可辨。本变更通过两份 delta 显式替换这些局部呈现规则，保持 Run 身份、历史顺序与取消／提交契约。

## Goals / Non-Goals

**Goals:**

- 用原消息、所属轮次和真实状态驱动一套连续体验；普通完成自然收束，异常有可操作的原对象入口。
- 在原有 DOM、历史与动作协调上增量实现，保持输入、选区、工具展开和阅读锚点。
- 将“停止”和“停止并发送”放在同一输入上下文，分别复用取消请求与服务端原子交接。

**Non-Goals:**

- 不重做 Work 导航、Service 应用、模型设置面板和全站主题，不引入组件库或新的设计系统。
- 不改 Core／Agent 协议、history schema、工具权限或包格式，不为装饰性摘要增加私有历史读取。
- 不新增待发送队列、跨关闭草稿存储、自动恢复执行或重放工具；本变更不包含 MicroVM 构建与发布。

## Decisions

### 1. 消息区统一视觉角色，原型是设计附件

以现有 `apps/ui-shared/tokens.css` 的正文、辅助文字、背景、分隔和危险／警告色为基线，只在消息区作用域定义气泡布局和图标位置。用户气泡按内容占宽，建议最大宽度约消息区的 78%，窄屏可调至约 84%；使用柔和浅底和约 20px 圆角。正文 14–16px、行高约 1.7–1.8，作者与工具摘要降为辅助层级；不把整页变成 OpenAI 或 Linear 主题。

发送图标放在用户气泡外的固定留白，不在气泡内永久预留空状态栏。发送成功移除图标后不改变正文宽度；长消息、纯图片及图文都保持原输入快照。弹层按滚动区可视边界定位，必要时翻到上方，不能被底部 Composer 裁切。复用现有 Tooltip／菜单或轻量详情方式，支持触摸点击、键盘打开、Esc 关闭和回焦点，不仅依赖原生 title。

[prototype.html](prototype.html) 冻结本轮交互方向，包含完整演示和状态切换。它使用合成内容、中文评审标签和模拟时序：样例工具路径、重试受理、核对结果均不是真实数据或产品验收。生产文案仍沿用现有双语 locale；原型不替代 360px、图片、Markdown 和真实请求验证。

### 2. 分开投影消息提交与执行状态

保留 `Message.submission` 的消息级归属，在 `models.ts` / `adapter.ts` 增加有界、内存内的发送尝试快照及明确失败重试动作。快照覆盖当前身份代次、Core／Work／Session、原提交键、文字／有序图片、输入模式、includeIdentity 对 prompt 的实际影响、模型／Thinking 请求语义及可选原取消目标；不得保存额外凭据或落盘私有输入。

| 事实 | 默认呈现 | 允许操作 |
| --- | --- | --- |
| 提交中 | 气泡外旋转图标 | 继续编辑后续草稿，防重复提交 |
| 明确未受理 | 失败图标 | 查看原因，用户显式重试原快照 |
| 受理未知 | 未确认图标 | 原 submissionKey 只读核对 |
| 已受理 | 移除提交图标 | 观察所属 Run，不重复铺受理回执 |
| Run 后续失败／中断 | 原回复处保留异常及部分输出 | 原 Run 诊断／恢复，不伪装成发送失败 |

原快照重试是一次新的显式尝试：先确认旧尝试确实未受理、当前身份及目标仍合法，生成新提交键并保留与原失败键的归属，在同一用户消息位置投影新尝试；晚到结果按尝试代次检查。未知请求没有此动作，查不到映射也不降级为已失败。已接受后执行失败不通过该重试入口再次提交 prompt。

重试使用原输入和原请求选择语义，不读取后续 Composer 内容；若原模型、图片或命令已经不合法，则在原消息解释限制并保留快照，不静默换成新选择。普通模型选择含“使用 Session／Work 默认”等语义时保持该原请求语义，不伪造未受理 Run 的实际模型。原取消目标变化或已有新活动 Run 时先核对并限制重试，不自动扩展取消授权。确认受理只消费匹配的原草稿版本与图片快照；以后编辑的文字、图片和设置都保留。

不要全局移除 `ActionState`。通过动作归属将已由消息／控制表现的 Chat 提交、停止及成功回执排除重复的通用 StatusLine，但保留在途、防重复、原键未知锁、设置错误以及其他业务反馈。停止、检查或重试失败必须仍在其原对象有恢复入口。

### 3. 一轮内的唯一主等待与稳定详情

继续以真实 Run、消息、工具身份组织 `messageMarkup` 和历史合并，不引入按文字／时间推测的“轮次”。同一已确认 Run 的作者与详情集中表达；无法证明归属时保持独立及未确认。

```text
User message  --> submission icon --> accepted Run
                                      |
                                      v
                         reply text --> tool activity --> reply text
                              ...            ...              ...
                                      |
                                      v
                                 actual terminal
```

图中的三个省略号表示不同阶段的同一主等待位置，不同时出现：无正文时在该轮回复位置显示轻量等待；正文流式输出时三点接在最后正文末尾；执行工具时移动到所属 Activity 摘要。多个同时运行的工具可在条目显示静态状态，主摘要只有一个等待组件。取消请求待确认仍表达真实取消中，观察断开时停止声称正在生成，改为原对象未确认和恢复。

安全 Markdown renderer 保持不变。末尾动效作为 UI 节点插入适合的段落／列表末尾；最后是代码块或表格时接在同一正文流的块后，不改用户代码和 Markdown 文本，也不创建新状态文案。选择文字、长表格横向滚动及未闭合代码围栏均需核对。

正常 running／succeeded 不再常驻一条 Run 状态行；在原轮次保留轻量详情入口，绑定原 Run，实际模型、Thinking、来源、错误和技术 ID 可按需查询。异常、部分正文、历史归属未确认等事实不能因去除噪声而隐藏。

### 4. 工具先解释已有事实，再展示原始内容

沿用 Activity 与工具调用的稳定键、默认折叠与失败聚合。单次调用优先用真实工具名称作摘要；只有已取得结构化公开字段才附对象信息。当前公开投影不足以还原文件名／调用参数时，回退到工具名和已有结果，不能把原型文件名套到真实调用，也不通过解析自由文本猜参数。

展开第一层显示调用名、实际状态与已有安全结果预览；进一步的“原始内容”仅展示已经取得的公开原文，输入字段缺失就不展示伪造输入。结构化结果没有既有可信专用预览时直接转义展示有界内容；沿用非文本、截断、未确认和工具错误表达。多工具 Activity 保留计数、失败数量、来源及正文交错顺序。

更新工具结果时复用同一详情节点，保持 `expandedActivity` 及子详情状态；结束不强制折叠。展开、滚动和新历史读取沿既有 `chatReading` 锚点保留规则执行，用户上翻不跟随新输出；仅在最新位置或显式选择回到最新后跟随。

### 5. 独立停止和组合提交是不同的命令

输入区保留单个主消息动作。独立停止是邻近的次级方块按钮，不要求新草稿或新模型设置可发送；主动作空闲时为发送，有合法新输入且已确认活动目标及组合能力时使用含停止和发送含义的组合图标。两者的标题与可访问名称明确区分，不能把一个无说明的停止方块复用为两个不相同命令。

| 当前事实 | 独立停止 | 主消息动作 |
| --- | --- | --- |
| 已确认空闲 | 不展示 | 输入合法时 Send |
| 已确认活动 Run | 可用，绑定其确切 ID 与来源 | 有合法新输入和组合能力时 Stop and send |
| 正在请求取消／cancelling | 显示等待并阻止重复取消 | 按当前未决交接保护，不另行提交 |
| 原提交结果未知 | 仅在另有可靠活动目标且取消合法时可用 | 保留原键核对，禁止重发 |
| 未确认活动状态 | 不猜目标，提供核对 | 不把未知当作空闲或自行取消 |
| 旧 Agent 无组合能力 | 保留现有合法 Cancel run | 保留 busy 与普通 Send 原兼容规则 |

独立停止通过 `adapter.cancelRun(id, targetRunId)` 发送取消，不消费任何草稿；目标来自已确认活动 Run，不从最新一条历史推断。网络失败、取消与成功竞争都显示原对象实际结果。其他 Session／Service 来源继续可辨，不能把取消描述为停止 Work 或撤销业务结果。

Stop and send 必须继续由 `adapter.send(..., cancelRunId)` 一次请求交给后端，按 CONV-CANCEL-SEND-001 协调校验、5 秒取消等待与新 Run 受理。绝不照抄演示定时器，把正式逻辑改成客户端 CancelRun 后再普通 Send。旧目标被新 Run 替代、取消超时及未知受理不自动扩大授权、不延迟补发；新草稿继续保留。

Enter 只触发当前明确可用的主消息动作；Shift+Enter、IME、字面输入、图片和五个网页 slash 动作沿旧逻辑。单独编辑／切换不取消；发送新 Run 前的现有校验仍先于组合取消。模型选择不影响已授权的独立取消。

### 6. 影响模块与验证边界

| 位置 | 责任 |
| --- | --- |
| `apps/desktop-webui/src/app.ts` | 消息／工具／详情层级、局部图标和弹层、独立停止与组合主动作、阅读与 DOM 保留 |
| `src/models.ts`、`src/adapter.ts` | 发送尝试快照、显式重试、原键核对、已确认停止目标；复用现有协议与观察 |
| `src/action-state.ts` 及其调用侧 | 有对应消息反馈时抑制重复通用回执，保留未知锁及其他动作反馈 |
| `src/chat-projection.ts`、`history-projection.ts` | 保持 Run／工具身份、结果单调合并及可取得公开内容；仅按实际需要调整 |
| `public/style.css`、`src/i18n/app.js`、`src/pending.ts` | 消息范围样式、双语图标名称／说明及复用全局三点；不全局替换令牌 |
| `test/feedback.test.ts`、`history.test.ts`、`recovery.test.ts`、`chat-projection.test.ts` | 请求次数、目标、草稿版本、异常恢复、展开／滚动和渲染回归 |
| `test/chat-controls-real-core.mjs` | 复用隔离 fixture 验证取消与原子组合动作，无真实用户 Work |
| `internal/desktopassets/static/` | 随 Desktop 构建同步生成，和浏览器源码同版 |

## Risks / Trade-offs

- [图标减少常驻文字但不易理解] → 用不同形状、完整双语名称、悬停／聚焦说明及点击恢复；失败／未确认不依赖颜色或纯 hover，弹层在窄屏可见。
- [删除重复状态时意外删除未知锁或 Run 错误] → 仅抑制重复呈现，不删除动作记录；验证真实未知保护、原失败对象和其他来源占槽并存。
- [失败重试使用后续输入或导致重复消息] → 捕获不可变输入和尝试代次，明确失败才允许新尝试；浏览器同时断言请求体、次数、原消息位置和新草稿保留。
- [把工具样例当成已提供的协议字段] → 依据现有 `Message.tool` 及已验证公开响应，缺少字段就回退；本变更不扩协议。
- [稀疏正文、Markdown 或历史补读让三点／详情移错轮次] → 使用既有稳定身份，保留历史投影回归和未知关联提示，验证长块及流式中间态。
- [照搬原型的模拟交接造成取消抢槽] → 正式实现只调用服务端组合提交；验证组合一次 POST、独立取消零新 Run、目标竞争及取消超时。
- [工具展开和弹层挤占窄栏] → 默认收起，结果与原始内容分层；按滚动区定位弹层，360px 及键盘核验裁切和焦点。

## Migration Plan

不涉及数据库、镜像或 API 迁移。实现后运行适用的针对性浏览器回归及隔离真实 Core 控制用例，构建 `@piwork/desktop-webui` 同步嵌入资源，再构建 Core／CLI 验证集成。原型演示通过不代表这些产品验收通过。

回退时一并回退 UI 源码及其嵌入资源；原有 Session／Run、提交键、历史和已输出正文保持既有格式，不清理用户数据或更换 Agent 镜像。仅呈现调整时不重复执行模型全套、Windows 重启或 MicroVM 性能采样。


## 实现核对

- 长回复恢复：移除跨冻结快照按 Run 缓存的完整读取标记，不因首个 Run 页已被最新 Session 页缓存而提前退出。每次原 Run 的恢复都沿本次冻结快照的 Run 游标读到末页，适用于运行中恢复后又产生新正文或 SDK／checkpoint 投影变化的情况；分页预算保持，Session 的更早页仍按用户操作读取。完整结果为空不覆盖已保存部分，身份切换或读取失败保持原中止／恢复规则。

- 连续聊天修复：终态补读先取得有界最新 Session 页，再在同一冻结快照补读原 Run；最新页没有连接已读轮次时，仅补读一个已读 Run 的尾页作为排序边界，不遍历整个 Session。已验证的排序边保留到对应已读内容清空，不随最近 16 个快照缓存淘汰。缺少可信连接时仍保持未知，不能用本地到达时间或正文强排。
- 历史异常呈现：部分正文、历史顺序或保存归属未确认使用气泡外的低权重图标；Popover 精确绑定 Work／Session／Run／消息，展开后说明事实并提供只读历史重查。正常连续聊天无异常图标，正文与工具摘要不铺技术提示。

- 重试快照和草稿版本映射各保留最近 16 次尝试，旧键链也限制为 16 个；只存在当前浏览器身份的内存，身份变化即清空。超过保留窗口的失败消息继续显示原错误，提示重新复制原内容，不重新读取后来草稿。
- 现有 Run API 使用 Session 的模型／Thinking 设置，没有逐次覆盖字段。重试要求当前已确认设置与原尝试选择语义一致；设置已改变时先提示恢复原设置，不自动改设置或换模型。原取消目标先做只读确认，仍由同一次带原 `cancelRunId` 的提交决定能否受理。
- 失败和未确认图标复用现有锚点 Popover，宽度 320px，按可视窗口折返；原因和恢复按钮仅在打开后显示。消息负责发送与重试反馈，ActionState 保留协调及未知锁。
- 工具首层使用已有公开结果的前 600 个字符，进一步展开已有完整公开预览；现有非文本和截断提示继续保留，不把它称为完整私有原始输出。原型中的路径和输入参数未带入产品。
- 空正文历史片段不会创建可见消息锚点，因此所属失败 Run 通过独立异常入口展示；其他 Session／Service 运行不覆盖它。“回到最新”定位在 Composer 上沿，随图片和设置反馈高度移动，避免被输入区遮挡。
- 原型的模拟交接只用于演示；产品保持原子提交、实际 Run 状态和原键核对。截图及临时输出在忽略目录 `dist/chat-interaction-ui/`，实际验收范围见 [acceptance.md](acceptance.md)。

- WARN 修复：消息状态锚点使用 Session 与 submissionKey 精确定位；重试错误先按身份代次更新原尝试快照，仅在原弹层、Work、Session、提交键及视图仍匹配时更新弹层，避免迟到失败覆盖其他消息的恢复入口。
- WARN 修复：同一 Session 的 Activity 通过仍存在的 Run／工具调用身份延续分组键，前插／追加工具不依赖新的首条消息重建容器。工具和原始内容的展开键独立绑定真实 Run／调用 ID；分组缓存仅保留工具分组，身份变化时清空，不改变协议或历史顺序。

- 阅读锚点补充：滚动记忆、布局恢复和渲染更新共用 `captureChatAnchor`／`restoreChatAnchor`。外层标题仍可见时保持其位置；外层已滚出视口时沿当前可见后代定位具体工具或原始预览，不再只保留整块 Activity 的起点。隐藏节点不参与锚定，处于最新位置时继续使用原跟随规则。
