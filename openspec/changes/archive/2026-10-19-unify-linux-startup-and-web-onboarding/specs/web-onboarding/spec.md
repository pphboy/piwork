# Spec Delta

## Purpose

提供统一 Piwork 服务端的首次网页配置流程，使安装者无需预设环境变量即可安全创建首管理员、保存模型及 CoreRuntime，并在本机或仅凭服务器 IP 的远程浏览器中观察真实准备状态、恢复中断配置，最终进入完整工作台。

## ADDED Requirements

### Requirement: 通过受限首次设置授权创建管理员

**Identifier:** ONBOARD-001

空安装 SHALL 提供网页创建首管理员的流程。创建前 MUST 验证仅由安装者取得的高熵、限时、一次性设置证明及当前来源/CSRF；匿名访问安装地址不得获得创建权限。证明 SHALL 通过启动端取得，普通访问日志、静态材料、浏览器持久存储及无认证状态响应不得包含它，不得复用 operator credential。页面兑换前 SHALL 从地址栏移除证明；兑换不代表已登录管理员。

所有网页、env 和 operator 首管理员创建 SHALL 共享“持久用户集合为空”的原子约束，并发最多一个成功。初始化后所有旧证明失效；账号禁用、密码变更或 runtime 缺失不得重新开放首次创建。证明到期、使用、遗失及响应未知 SHALL 有安全恢复/读回方向，不自动重复创建。

#### Scenario: 无环境变量首次创建
- **WHEN** 安装者启动空安装、使用有效设置链接并提交合法账号密码
- **THEN** 创建一个持久管理员并关闭首次创建入口，随后可正常登录；不要求 CLI、预设账号或模型 env

#### Scenario: 匿名访问或证明失效
- **WHEN** 远程匿名访问者提交创建请求，或证明错误、过期、已使用、来源/CSRF 不匹配
- **THEN** 创建被拒绝且没有账号变化，界面区分设置授权问题与密码错误并提供取得新链接的方向

#### Scenario: 并发创建和后续禁用
- **WHEN** 两个网页或网页与 env 同时初始化，或已有安装后来失去启用管理员
- **THEN** 首次事务至多一个成功，已有用户不被覆盖，后续状态不重开公开 bootstrap

### Requirement: 在管理员会话中完成模型与 Runtime 引导

**Identifier:** ONBOARD-002

管理员 SHALL 在引导中查看 Docker 状态，填写完整模型的 Model ID、API type、Base URL、API Key 并选择性 Test，随后由服务端使用随当前版本内嵌的发行 Agent 引用保存 CoreRuntime。Agent 镜像是发行默认值，MUST NOT 提供手填、选择或高级覆盖入口；与 Runtime 管理页遵守 SUI-CFG-002 的同一约束。名称可选，Test 失败不禁止合法保存，不要求创建 Provider、能力模板或重复输入 Key。真实模型 Test SHALL 由用户显式触发，首次启动和保存不得隐式发送模型请求。

模型保存与 runtime 绑定 SHALL 分别呈现已确认事实；后一步失败不能把已保存模型显示为失败或自动重复创建。仅有效管理员可以写模型/runtime，普通用户看到真实待配置状态。旧持久模型、引用和 Key 可用性 SHALL 可直接复用。

#### Scenario: 一个引导完成首次配置
- **WHEN** 管理员填写合法模型连接并保存
- **THEN** 模型和引用式 runtime 可逐步保存，Agent 引用由服务端从同版发行自动取得；页面没有 Agent 镜像输入或高级覆盖，无 Provider/模板/模型 env 前置步骤，不预建 Work

#### Scenario: 发行 Agent 不可取得
- **WHEN** 同版默认 Agent 拉取失败或内置发行引用缺失/无效
- **THEN** 显示真实准备状态及重试或发行修复方向，已保存模型保持，不要求用户填写替代镜像、不新增高级覆盖

#### Scenario: Test 失败但配置有效
- **WHEN** 用户显式 Test 得到目标认证或网络失败，随后选择保存
- **THEN** 检查失败与保存事实独立，允许合法配置保存，Key 不回填或记录，管理员会话不因供应商错误失效

#### Scenario: 模型已保存而 runtime 未确认
- **WHEN** 模型保存成功，但 runtime 保存失败或响应丢失
- **THEN** 保留模型引用并提供只读核对，用户显式恢复原步骤，不重新创建模型或隐式重发未知修改

### Requirement: 引导状态由持久配置及真实准备状态驱动

**Identifier:** ONBOARD-003

引导 SHALL 区分需要创建管理员、需要登录、Docker 不可用、模型/runtime 未配置、配置已保存、依赖准备中、准备失败及可进入工作台。网页在缺少这些运行条件时仍可打开，不能等待完整 Work readiness 才提供引导。保存确认、镜像拉取、基础就绪、完整交付就绪和具体 Work 能力 SHALL 分别表达，不假造进度或把 health 等同于 ready。

关闭/刷新页面或重启服务器后 SHALL 读回已确认的持久状态并继续缺失步骤；不依赖浏览器完成标记，不保存密码/Key 草稿。用户可以离开等待页面，后台准备按既有重试/取消规则执行，不自动创建 Work 或提交 Run。

#### Scenario: 缺模型或 Docker 仍可打开网页
- **WHEN** 空安装启动，或已保存 runtime 但 Engine 不可达
- **THEN** 网页和健康检查可用，显示具体缺项/失败及恢复入口；Work 准入仍按真实状态关闭

#### Scenario: 关闭后恢复
- **WHEN** 模型或 runtime 已保存，用户关闭网页或服务器重启后重新登录
- **THEN** 已确认配置保持，页面继续尚未完成阶段，不要求重建账号、重输已有 Key 或重建模型

#### Scenario: 准备失败后恢复
- **WHEN** 镜像拉取暂时失败随后网络恢复，或配置被修正
- **THEN** 当前代次继续准备并更新真实状态，旧代次结果不覆盖新配置，等待不阻塞管理页面

### Requirement: 完成引导后保留后续配置入口

**Identifier:** ONBOARD-004

首次配置完成后 SHALL 进入真实工作台并保留管理员重新查看/修改模型、Runtime 和默认 Work 的入口。全局默认变化只影响后续新 Work；已有 Work 的独立配置、运行身份、历史与 desired/active 语义保持。首管理员 env 只影响空安装，不能作为持续管理账号或模型的来源。

#### Scenario: 重启进入已有安装
- **WHEN** 已初始化安装再次启动
- **THEN** 浏览器登录后进入对应工作台或实际故障恢复，不重新执行首次创建或重置模型

#### Scenario: 修改默认不改变已有 Work
- **WHEN** 管理员在后续设置中更改默认模型，或服务端升级后显式保存 runtime 使用新的内置 Agent 引用
- **THEN** 新 Work 使用已保存的新默认，已有 Work 保持原配置且不自动 Apply、重启或切换模型；仅启动或读取不会自动改写持久配置，也不出现镜像手填入口
