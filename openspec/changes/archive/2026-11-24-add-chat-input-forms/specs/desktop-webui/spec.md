# Desktop Chat · 消息内输入表单

## ADDED Requirements

### Requirement: 在 Agent 提问的消息内作答

**Identifier:** DWUI-CHAT-FORM-001

Desktop Chat SHALL 在所属 Assistant 消息内按声明顺序呈现单选、多选、文本字段及一个明确的确认发送入口，并保留常规聊天输入框。只有完整且有效的 Assistant 表单声明能产生控件。输入和选择 SHALL 仅修改本地答案。用户、工具及无效声明中的内容沿用原有安全呈现。

#### Scenario: 填写三种问题

- **WHEN** 用户在周计划表单中先后选择两个不同目标，勾选两个任务，并在文本字段输入「周三下午留空」
- **THEN** 单选只保留最后选中的目标，多选保留两个任务，文本保留原意。短选项横排，空间不足时换行，已选状态清晰可辨。确认前会话未新增用户消息，常规重绘保留当前填写

#### Scenario: 表单尚未完整或不受支持

- **WHEN** Assistant 仅流出半段声明，或正文含有无法解析的声明、未知字段类型
- **THEN** 对应内容以安全的只读形式呈现，用户可用聊天输入框作答；用户消息、工具结果和普通代码示例也不会变成表单

### Requirement: 一次确认作为一条普通用户消息发送

**Identifier:** DWUI-CHAT-FORM-002

确认时 Desktop SHALL 将本次已填写的问题和答案按题序组成一条可读的普通文本消息，只向表单所属且仍选中的 Session 提交一次。沿用现有聊天准入、提交状态及历史合并语义。表单提交 SHALL 保留聊天输入框中独立的文字和附件草稿；直接发送聊天草稿时只发送用户在该入口确认的内容。

#### Scenario: 确认周计划答案

- **WHEN** 用户选中「完成原型」，勾选「访谈」「评审」，填写「周三下午留空」后确认
- **THEN** 同一会话的一条用户消息显示三道问题及对应答案，Agent 可在下一轮据此继续；重复点击同一在途确认不产生第二条提交，重开历史仍只看到一条已受理的回复

#### Scenario: 直接输入替代表单

- **WHEN** 用户看到表单后在常规聊天输入框发送「计划改了，先只安排周一」，没有确认表单
- **THEN** 本次只提交这条普通消息，表单内尚未确认的选择不进入消息

#### Scenario: 会话切换或结果未知

- **WHEN** 用户切换 Session，或表单消息已提交但受理结果未知
- **THEN** 原表单不能向新 Session 投递；未知结果沿用原提交键核对，不自动重发或把另一会话的状态当成成功
