# Design · Chat 消息内输入表单

## Context

选定的[原型 A](https://piwork-chat-input-lab.pphgee.chatgpt.site/?variant=A)确定了表单在消息中的位置和确认方式。该示例的第二道选择题是单选；实际验收使用用户最终指定的「目标单选、任务多选、时间限制文本」。

`apps/agentd/src/package-resources.ts` 已将文件交付等回复约定注入模型上下文。`apps/desktop-webui/src/chat-markdown.ts` 对 Assistant 正文做有界 Markdown 解析，当前把代码块输出为转义文本。`app.ts` 管理消息呈现、输入框草稿和动作反馈，`adapter.ts` 的发送方法已处理普通文本、Session、模型设置、提交快照、受理及未知结果核对。

## Goals / Non-Goals

表单是当前对话里收集一次回复的入口。沿用既有消息正文和历史格式。范围限于单选、多选、文本；通用 AG-UI 协议对接、任意布局、脚本、Service Action 和独立表单存储均超出本次范围。

## Decisions

### Agent 用一个保留的 Markdown 围栏声明表单

Agent 通过现有模型上下文约定获知，在 Chat 需要用户答复才能继续时，默认将实际问题写进一个顶层、显式闭合的 `piwork-form` 围栏，并放在回复末尾。开头可用一句话说明缘由，发完表单即结束本轮等待用户回复。用户明确要求纯文字提问时按该要求作答。该文本约定沿用当前流式事件、持久历史和消息提交。

````markdown
请告诉我下周的目标、任务和时间限制。

```piwork-form
{"fields":[
  {"type":"single","label":"本周最重要的目标是什么？","options":["完成原型","整理方案"],"required":true},
  {"type":"multi","label":"哪些任务要排进去？","options":["访谈","评审","写文档"],"required":true},
  {"type":"text","label":"还有什么时间限制？"}
]}
```
````

`fields` 为非空的有序列表，`label` 为非空文本，选择题的 `options` 为非空且可区分的文本列表。选择控件与页内草稿使用数组序号，提交时按声明顺序取回选项文本，避免 HTML 换行归一化丢失选择。设计默认允许选填，`required: true` 表达必答。全部为空时不产生消息。文本按字面处理，选项和问题均不解释为 HTML、链接动作或命令。

### 只在当前可继续的提问上开放作答

Desktop 在既有 Markdown 预算内检查顶层代码块及原始结束围栏。只对符合声明形状的最终提问提供控件，普通嵌套示例和非法声明沿用安全代码展示。流式片段、分页不完整或归属尚未确认时保持只读；一旦取得完整回复按同一规则重绘。交互只开放给当前 Session 最近一轮可确认完成、尚无后续用户消息的提问，并遵循现有 Work 发送准入。回看较早的有效表单可读到题目，历史中的用户回复提供实际答案。

使用组件规范中的单选组、复选框组、带标签的文本框和一个确认按钮。页面内按现有身份、Work、Session 和原消息身份保存暂存答案，处理聊天重绘时保留输入和焦点；发送时复核来源。普通输入框始终可独立作答。刷新后重新从消息正文呈现，未提交答案仅在本页内存中保留。

补充原型选定 A 的视觉样式。细侧线标出消息内的提问区域，短选项排成一行并按可用宽度换行。选项保留原生单选和复选控件，选择与键盘焦点各有清晰的视觉反馈。短文本以紧凑可扩展的输入框呈现。

### 将答案显式提交为文本

按题序逐行输出「问题 + 答案」，多选按选项声明顺序列出，略过未填选填题。提交快照示例：

```text
本周最重要的目标是什么？ 完成原型
哪些任务要排进去？ 访谈、评审
还有什么时间限制？ 周三下午留空
```

复用 `adapter.send` 与 Chat 的提交反馈，绑定原 Session、提交键和原快照。输入模式为普通文本，不读取独立聊天草稿中的文字或附件，不传取消 Run 的意图。忙碌或缺少模型准入时遵循同一发送限制。明确未受理时保留本次答案并使用原有失败恢复；结果未知时只允许原键核对。受理后由同一条用户消息承载答案，恢复、刷新和分页不重新发送。这样无需跨请求挂起 Agent，也无需增加表单回调。

## Risks / Trade-offs

- **代码围栏可能只是示例。** 保留标记限顶层末尾的单个合法声明。指导在演示协议时采用外层普通代码围栏。原始文本、工具结果、超预算内容沿用现有回退。
- **同页反复渲染容易丢失正在填写的答案。** 草稿归原消息，提交时固定快照。测试穿插重绘、切换会话和结果未知，避免把输入或回执交给其他消息。
- **模型可能输出不符合约定的格式。** 保留可读正文和手动回复入口；不增加自动修复轮次。旧客户端仍能显示代码块，旧消息无需迁移。

## 本机交付

新建 Work 从 Core 的默认 Work 配置捕获基础镜像。`internal/coreapp/work_create.go` 负责创建时的捕获，`internal/coreapp/default_work_patch.go` 负责合并管理员更新并安排运行时准备。在 `17891` 的现有开发安装使用独立本地 tag 构建 production Agent，单独更新 `default-work.baseImage`。该设置在后续创建时生效，已有 Work 继续使用各自捕获的上下文。验收同时核对线上默认镜像与普通 New Work 的首次表单路径。
