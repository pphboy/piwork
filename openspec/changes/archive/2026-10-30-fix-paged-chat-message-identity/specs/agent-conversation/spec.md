# Spec Delta

## MODIFIED Requirements

### Requirement: 分页历史能力独立协商且保留原始历史

**Identifier:** CONV-HISTORY-COMPAT-001

新版分页历史与配套轻量响应 SHALL 通过独立能力版本明确协商，不提高基础聊天准入门槛或自动替换固定 Agent 镜像。旧 Agent 未支持时 SHALL 明确不支持新版通道，保留原本可用的基础聊天与旧读取；新版客户端不得把缺少能力、读取失败或部分结果当作完整空历史，也不得将不断重试旧整份接口作为长会话恢复方案。

新增读取投影 SHALL 不改写 SDK 原文、消息树、既有 history schema、完整包格式、Session context、幂等记录或导入历史执行边界。重启与完整包导入后 SHALL 可重建读取能力并从新快照读取保留历史；不要求恢复旧进程的游标。超限、传输不完整、游标失效与 JSON 格式错误 SHALL 可区分，正常大历史不再因总量被误报为 `MALFORMED_RESPONSE`。

旧读取返回可靠的 Run、SDK 消息和内容块身份时，客户端 SHALL 将其与受理输入及已验证的实时来源对应，避免普通发送结束后出现重复的一问一答。仅角色相同或文字相同不构成对应证据；原始来源缺少可靠关联时仍不得伪造身份、丢弃已输出部分或新增模型执行。Core 更新和登录原数据 SHALL 不被当成固定 Work Agent 已升级的证明；能力以实际运行 Agent 的协商结果为准。经所有者明确授权的镜像升级 SHALL 走既有受管 Apply、备份与迁移流程，保持原 Session、SDK 历史、Run 和幂等身份，升级失败遵守原恢复约束。

分页能力声明 SHALL 仅证明相应分页通道和基础范围契约可用，不得被当作所有可选实时来源字段均存在的证明。对于支持分页但缺少部分或全部来源坐标的固定 Agent，客户端 SHALL 保留分页读取，并在已有可信事件来源、工具边界和分页范围证据下对应实时输出；不得因字段缺失强制换镜像、退回整份历史轮询、提高聊天准入门槛或重新执行消息。来源坐标可用性 SHALL 按实际返回内容处理，已经提供的坐标及其冲突校验不得被忽略。

#### Scenario: 旧 Agent 和未声明新 profile 的客户端
- **WHEN** Work 仍运行旧 Agent，或旧客户端使用原接口且不声明新 profile
- **THEN** 原有可用能力保持，新通道不支持有明确说明，不自动换镜像、截断历史或发送新的 Run

#### Scenario: 重启与完整包往返
- **WHEN** 含长会话、图片、模型与工具历史的终态 Work 重启，或完成导出导入并由用户显式 Start
- **THEN** 新快照仍能完整读取原公开历史，原始私有内容及包格式不变，导入和只读查看不执行历史模型或工具

#### Scenario: 新 Core 连接旧固定 Agent
- **WHEN** Core 已更新，但 Work 的固定 Agent 仍只支持旧聊天和完整历史读取
- **THEN** 按实际协商使用原通道，已确认消息转换只显示一次；不以读取或发送为理由自动更换镜像，也不通过阻止原本可用的聊天规避兼容问题

#### Scenario: 明确升级后沿用原会话
- **WHEN** 所有者通过受管 Apply 将旧 Work 升级到支持分页历史的新 Agent
- **THEN** 原 Session、SDK 历史、Run 与幂等身份保留，新读取能力重新协商；不重新执行旧消息，也不要求新建会话或清空内容以消除重复

#### Scenario: 支持分页的旧固定 Agent 缺少来源坐标
- **WHEN** 新客户端连接仍支持分页协议但缺少可选实时来源坐标的固定 Agent
- **THEN** 保留原分页通道和原 Agent，在可信来源与已读范围能证明对应时只显示一份输出；普通发送、登录和历史读取不自动升级镜像、重建 Session 或新增模型执行

#### Scenario: 同一分页快照中的来源字段混合可用
- **WHEN** 同一快照的一部分内容块带实时来源坐标，另一部分缺少坐标
- **THEN** 分别核验显式坐标及可证明的兼容覆盖，不将整份快照一概当作有坐标或无坐标，不因字段混合忽略范围缺口、字节冲突或未覆盖正文
