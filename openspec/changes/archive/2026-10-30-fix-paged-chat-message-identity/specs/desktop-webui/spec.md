# Spec Delta

## MODIFIED Requirements

### Requirement: Chat 按真实对话顺序合并历史与实时内容

Desktop SHALL 在同一 Session 内按可信历史顺序和已知 Run/消息身份合并分页历史、实时消息与工具活动。旧消息及其 Run 状态 SHALL 保留在所属轮次，不得因读取、合并或新消息受理而移到新轮次之后；无法确认归属或顺序的内容 SHALL 保留并明确未确认，不得按文字或时间猜测绑定。历史重读 SHALL 保留尚未在历史中确认的已显示输出，直到同一内容被完整替换或明确表明无法恢复，且不得重复显示。页面刷新、游标过期恢复及加载更早消息 SHALL 不改变真实顺序或隐式提交、取消 Run。

旧 Agent 的完整历史接口 SHALL 遵守同一逻辑消息只显示一次的约束。对已确认属于同一 Run 的受理输入，文本或图片落盘后 SHALL 接替原提交消息；对有可靠事件起点、真实工具调用边界和字节范围对应的 Agent 正文，保存历史 SHALL 接替已覆盖的实时范围。源 ID 不同本身不得造成重复副本，相同文字本身也不得作为删除或跨消息绑定的依据。没有对应证据的独立 SDK 消息及尚未覆盖的已显示正文 SHALL 保留；不能通过整轮清空、截短正文或重新执行来消除重复。

分页能力可用而可选实时来源坐标缺失时，Desktop SHALL 继续按已确认的 Run 来源、事件接收起点、真实工具调用边界及同一冻结快照的连续字节范围建立覆盖关系，使同一输出只显示一次。分页的内容块身份、范围完整性和顺序约束 SHALL 保留；只取得片段或缺少区间起点不得视为整份历史，也不得按文字相同推导关联。已验证的覆盖部分 SHALL 接替实时副本，未覆盖的原始正文 SHALL 保留一次供后续增量和补读继续确认。存在显式来源坐标时 SHALL 沿用其范围校验，不能以兼容推导绕过坐标或字节冲突。

文本事件分片及其重放 SHALL 保持实际字节内容完整，同一事件序号的不同有效分片不得被误当作重复事件丢弃。实时、保存及未覆盖尾部之间的接替 SHALL 保留稳定的显示关系、草稿、工具展开与当前阅读位置，不得因来源键或覆盖长度变化使用户正在阅读的内容跳动。

#### Scenario: 旧取消轮次与新的数字消息
- **WHEN** 已保存对话中旧 Run 为 cancelled，随后同一 Session 的“1”和“4”两次 Run 成功，且历史和实时消息混合加载
- **THEN** 旧取消状态随旧轮次显示在“1”和“4”之前，两次新 Run 各自保留成功结果并可在其详情核对，消息及正文不重复

#### Scenario: 历史不完整或读取失败
- **WHEN** 历史分页、Run 重读或游标过期恢复尚未覆盖已显示的实时正文，或读取失败
- **THEN** 保留已知正文与原 Run 归属并提示未确认，不用空结果覆盖，不猜测缺失内容

#### Scenario: 同文不同轮次
- **WHEN** 不同 Run 含相同用户或 Agent 文本、相同工具名称，历史分页以不同顺序返回
- **THEN** 按消息和工具的可确认身份合并，各轮次保持独立，不按文本、工具名或最近 Run 去重或绑定

#### Scenario: 连续发送后补读终态历史
- **WHEN** 同一 Session 连续完成多个 Run，终态补读按 Run 分别返回，或最近快照缓存发生淘汰
- **THEN** 通过同一冻结快照的有界 Session 页及必要已读轮次边界保持可靠顺序，已验证关系不被缓存淘汰遗忘，正常消息不误报顺序未确认；不自动遍历整份历史或提交业务动作

#### Scenario: 真正的历史异常按消息查看
- **WHEN** 部分正文、顺序或保存归属仍无法可靠确认
- **THEN** 原消息外显示可访问的状态图标，点击／键盘展开原消息的具体事实及只读重查入口；正文和 Activity 摘要不常驻技术警告，新草稿、展开及阅读位置保持

#### Scenario: 运行中恢复后终态包含多页新正文
- **WHEN** 原 Run 在运行中已做过历史恢复，之后保存的正文超过一页并进入取消、失败或中断终态，最终结果为空或不存在
- **THEN** 在本次冻结快照内继续沿该原 Run 的游标补齐可取得正文，不因首个页已缓存或旧快照曾读完而提前退出；正文保持一次、真实终态不变，不遍历整个 Session 或提交新的消息

#### Scenario: 旧协议发送完成后接替实时气泡
- **WHEN** 旧 Agent 不支持分页历史，发送产生一条受理用户消息及一条 Agent 实时回复，随后完整历史以另一套 SDK ID 返回同一轮且来源对应已确认
- **THEN** 每条逻辑消息只显示一次，原提交状态、实际内容和 Run 归属保留；重复补读及刷新不增加副本，也不创建新的 Run

#### Scenario: 有工具边界的合法同文与分块
- **WHEN** 同一 Run 在不同真实工具调用前后输出相同正文，或同一输出被保存为多个 SDK 内容块
- **THEN** 按已确认的工具调用边界和来源覆盖范围合并实时副本，独立正文位置及 SDK 消息身份仍保留；不因文字相同删掉合法内容

#### Scenario: 历史只覆盖部分实时正文
- **WHEN** 保存历史只确认覆盖实时正文的一部分，或取消、失败、中断后仍有不可确认的尾部
- **THEN** 已确认部分不会同时显示实时和保存副本，未覆盖正文及真实终态继续可读，来源未确认沿用原消息状态入口；连续补读不累积新的尾部副本

#### Scenario: 切换身份后旧合并结果晚到
- **WHEN** 合并或恢复读取在 Core、账号、Work、Session 或运行实例切换后才结束
- **THEN** 晚结果和来源映射均不得进入新对象，不覆盖新草稿或触发重新提交

#### Scenario: 分页支持但缺少实时来源坐标
- **WHEN** 固定 Agent 支持分页历史但不提供可选实时来源坐标，客户端完整观察一次正常发送，终态分页返回另一套 SDK 内容块身份且范围足以验证对应
- **THEN** 一次发送只有一次 Run 提交，每条受理输入和回复各显示一次，正文与真实终态完整；重复补读和刷新不增加副本，也不要求升级 Agent

#### Scenario: 分页缺少起点或存在范围缺口
- **WHEN** 缺少实时来源坐标的分页只包含某轮输出的中段、工具边界缺失或正文范围有缺口
- **THEN** 不推导未经证明的来源对应，不丢弃已显示正文；在同一冻结快照的原 Run 必要范围补齐证据后接替已验证副本，不自动遍历整个 Session 或提交新消息

#### Scenario: 同序号文本分片与断线重放
- **WHEN** 同一文本事件以多个带字节偏移的有效分片传输，包含中文或多字节字符，断线恢复后重复返回部分已读分片并继续追加
- **THEN** 每个有效字节范围只计入一次，不因事件序号相同漏掉后续分片；历史接替后正文仍完整且只显示一次，冲突分片沿用原有失败保护

#### Scenario: 来源接替时保持正在阅读的正文位置
- **WHEN** 用户正在阅读长回复中段并保留新草稿、输入框选择范围或已展开工具，历史覆盖由前缀逐步增加至完整正文
- **THEN** 已确认前缀与未覆盖尾部不重复，正在阅读的内容位置保持，草稿、输入框选择范围和工具展开不被来源接替重置
