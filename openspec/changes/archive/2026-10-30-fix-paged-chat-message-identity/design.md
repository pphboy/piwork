# Design

## Context

动机见 proposal.md。当前 `supportsHistory` 只确认分页协议 1、profile 和预算；协议中的 `streamId/streamOffset` 是可选字段。实际运行 Core 为 `777aaf8`，报告中的固定 Agent 聊天契约为 3，分页可用，但该轮所有保存文本都没有来源坐标。

`resumeRun` 仅在不支持分页时调用 `LegacyHistoryProjection` 记录接收起点及工具边界。分页分支继续创建 `Run-text-sequence` 显示对象；`HistoryProjection.project` 可按显式流坐标、同 ID 范围和已验证 checkpoint 接替，但不能为缺少坐标的 SDK 块证明来源，因此终态补读把正常实时副本保留为未确认。

只读回放报告轮次得到一条用户消息、两份 401 字节的回复，其中一份未确认；已保存来源只有一份，94 个实时文本帧合成后与它完全一致。以完整单页转换后接入已有来源追踪，可得到一问一答且正文相同。这只证明来源规则可用，不证明可将任意分页片段送进整份历史合并器。

## Goals / Non-Goals

**Goals:**

- 为三类组合提供一致的逻辑身份保证：不支持分页、分页无来源坐标、分页有来源坐标。
- 使分页缺少可选字段时仍能使用客户端已经观察到的真实来源证据，并保留分页完整性、工具顺序和字节预算。
- 保存原始实时来源，投影只暴露未覆盖尾部，来源接替时维护阅读锚点。

**Non-Goals:**

- 不按全文相等、角色或最近 Run 猜测身份；不能证明的内容仍保留。
- 不更改分页公开版本、Agent 历史格式、SDK 文件或发送／取消业务语义。
- 不升级固定 Work Agent、不修改默认镜像、不改 MicroVM 启动机制、不增加真实模型或整机重启验收。

## Decisions

### 1. 提取统一实时来源记录，保留两种历史适配器

新增浏览器纯模块 `live-message-sources.ts`，承接并整理当前 `LegacyHistoryProjection` 中可复用的 Run 输入、原始实时正文、接收起点、事件分片及真实工具边界记录。`adapter.ts` 在受理和观察处对两种历史通道均记录来源；每个身份代次、Work、Session 使用一个来源实例。`legacy-history-projection.ts` 与 `history-projection.ts` 分别适配旧 SDK 整份响应和分页范围，共用来源及覆盖核验，避免产生第三套相互独立的去重规则。

```text
accepted input + observed text fragments + real tool boundaries
                              |
                   shared live source records
                      /                  \
          legacy SDK adapter       paged range adapter
                      \                  /
                 verified coverage + display relations
                              |
                    one logical conversation
```

不直接让分页调用 `LegacyHistoryProjection.merge`：该入口不知道分页中缺失的首段、其他页或工具边界，会错误地把局部响应当完整历史。不删除现有“相同文字但无来源证据时保留两份”的保护测试。

### 2. 分页在自身范围模型上建立可验证的来源覆盖

`HistoryProjection` 继续持有 SDK entry/block、冻结快照顺序及已读字节区间；其适配器只向共享核验器提供已验证的范围和边界，不改写服务端页或伪造 `streamId`。

- 显式流坐标有效时沿用现有逐字节校验；坐标或内容冲突不能降级成另一次猜测匹配。
- 缺少坐标时，实时区间必须具有可靠起点：从 Run 起点观察，或已观察并确认相同工具调用边界。SDK 一侧也必须确认该区间起点和参与核验的连续范围。
- 优先使用 `loadSavedRun` 已在同一冻结快照中补齐的 Run 范围作为 SDK 侧证据；接收或恢复入口明确传递范围开始、页归属和游标耗尽事实。不能仅凭内容块从字节 0 开始、Session 页无下一页或角色相同就宣称整个 Run 范围已确认。
- 一侧缺少起点、页范围有缺口、跨快照关系不能证明或工具调用不对应时，保留原事实。已有原 Run 范围补读取得证据后再接替；沿用当前有界读取，不遍历整份 Session。
- 在同一已确认工具区间逐字节比较原始实时源与连续 SDK 内容。完整覆盖消除实时副本；可确认的开放区间前缀覆盖只保留一次原始源的未覆盖尾部。关闭区间出现长度或内容冲突时保持保护，不能截短原文。
- `resultRef` 只辅助确认其指向的末尾结果，不能吸收同一 Run 工具前的其他正文。SDK 多块身份和独立消息位置继续保留，同文不同轮次或不同工具区间不能合并。

兼容推导结果是局部覆盖证据，不是整个 Work 的“有坐标／无坐标”布尔状态。同一页中两类内容块可以混合存在。

### 3. 文本分片按范围接收，显示裁剪不改变来源

分页文本流可能将同一事件序号拆成多个 `byteOffset/totalBytes/complete` 分片。共享来源接收必须沿用 `historyEventParts` 已有的偏移、冲突和完成校验：以事件序号和片段偏移识别重放，完整保留同序号的后续有效分片，事件完成后再推进完成游标。旧版无分片文本继续作为一次有效增量处理。

原始来源独立于保存前缀及尾部显示；后续增量只能追加到原始来源。确认覆盖后释放不再需要的正文缓存；停止观察保留尚未覆盖的已显示内容，身份切换、对象删除和晚响应检查不得把来源带入新对象。

### 4. 让显示别名和阅读锚点跟随同一输出

`models.ts` 只增加必要的临时显示／来源信息，SDK 的持久 ID 不被界面别名替代。`app.ts` 对已确认属于同一输出的来源使用稳定显示关系；若保存分块或前缀接替导致节点拆分，按同源文本位置迁移当前阅读锚点，不能只查找已经消失的 `Run-text-sequence` 或不断变化的 `remaining-N` 节点键。

工具继续使用真实调用 ID 保留 Activity、原始输出展开和焦点；输入草稿及输入框选择范围沿用现有保持机制。此变更覆盖与来源接替直接相关的阅读锚点偏差，不引入新的气泡样式或页面重设计。

### 5. 用实际兼容组合验证，交付同一构建输入

先用合成数据复现“分页协议可用、聊天契约 3、没有来源坐标、SDK ID 与实时 ID 不同”的正常发送链路，再补必要的分片、部分覆盖和边界保护回归。有坐标分页和 501 完整历史沿用既有回归，避免只换测试条件就宣称修复。

构建工作台及嵌入资源的 Core/CLI，通过已有 MicroVM 本地构建打包入口交付到桌面。Agent/helper/QEMU/Guest 基础组件未改变时可复用匹配依赖，但必须保留真实身份与许可证，重新校验 EXE 内 Guest/Core 和 UI 输入身份。已有 GUI 文件保留，不发布镜像。

原 Work 仍保持报告中的旧固定 Agent、数据盘、账号及模型选择。最终核验由两部分组成：合成浏览器实际发送仅产生一次 Run，接替后显示一问一答；原会话只读回放既有事件与保存范围，在最终构建对应的投影中也得到一问一答且正文一致。真实环境不新增模型提示或 Run，不能以“EXE 中存在新 Core”代替行为核验。

## Risks / Trade-offs

- [从分页中段推断区间起点导致误并] → 显式传递同一快照的 Run 范围与工具边界证据，缺口未补齐前保持保护。
- [重用旧记录逻辑时丢掉同序号后续分片] → 以事件及偏移校验重放，覆盖多字节正文、断线和追加。
- [按工具结束顺序改变正文边界或吸收合法同文] → 工具开始定义区间，调用 ID 和顺序参与核验，结束事件只更新状态。
- [裁剪显示尾部后继续追加导致重复或截短] → 来源保存全量未确认正文，显示片段仅由覆盖事实派生。
- [来源键变化造成阅读跳动] → 同源显示关系与文本位置迁移锚点，定向验证保存前缀扩大及最终接替。
- [旧 Agent 升级掩盖兼容失败或测试范围膨胀] → 原 Work 镜像保持不变，使用必要合成回归和一次原会话只读核验，不做批量性能采样。

## Migration Plan

1. 固定合成的分页无坐标回归，保留原保护用例及三类能力组合。
2. 提取共享来源记录，接入分页范围核验、终态／恢复路径和显示锚点迁移。
3. 执行受影响的单元、浏览器、边界和构建检查，生成匹配 Core/CLI 与 MicroVM GUI，校验原始构建身份和内嵌文件。
4. 原 Work 无活动 Run 时，通过既有正常退出流程切换新 GUI／软件 VM，沿用同一数据盘；不重启 Windows 宿主，不升级 Agent 或修改模型。
5. 只读打开报告会话并回放已有来源，记录必要非敏感结果。若新 GUI 启动或核验失败，正常退出后重新打开保留的旧 GUI，沿用同一数据；兼容修复不涉及历史迁移。
