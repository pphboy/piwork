# Proposal

## Why

实际 Windows MicroVM 已运行更新后的 Core，但 Work 固定的旧 Agent 支持分页历史且不返回实时流来源坐标，绕过了上次只接入完整历史通道的来源追踪，普通发送后仍把实时回复与 SDK 保存回复各显示一份。已在报告会话只读复现：同一轮保存正文与 94 个实时文本帧合成正文均为 401 字节且完全一致，分页合并仍得到两份回复；需要补齐分页通道的身份衔接，不能用升级 Agent 掩盖客户端兼容缺陷。

## What Changes

- 分页与旧完整历史通道共用受作用域约束的实时来源追踪，保留事件起点、文本分片、工具边界和原始未覆盖正文。
- 分页存在可信来源坐标时沿用现有覆盖校验；缺少坐标时，在同一冻结快照内依据已确认的 Run 范围、事件来源和真实工具边界验证字节覆盖，接替对应的实时副本。
- 保留分页坐标、内容块身份和原顺序；页面片段不视为整份历史，缺少区间起点、范围不完整或内容冲突时不猜测关联。部分覆盖只保留一次未覆盖尾部，合法同文继续独立显示。
- 普通终态补读、重复读取与游标恢复使用相同来源规则；接替时保留草稿、工具展开、稳定显示关系与阅读位置，覆盖上次归档记录中的相关阅读锚点偏差。
- 以“不支持分页、分页无来源坐标、分页有来源坐标”三个组合做定向回归；重新构建包含修复的 Core/CLI 和桌面 MicroVM GUI，在保留旧固定 Agent 的原会话做只读核验。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `desktop-webui`：明确缺少可选实时来源坐标的分页历史仍须在可靠证据下唯一接替实时消息，保留未覆盖正文与阅读位置。
- `agent-conversation`：区分分页能力与可选来源坐标的实际可用性，保留旧固定 Agent 的分页兼容，不自动换镜像或重发消息。

## Impact

- 主要影响 `apps/desktop-webui/src/adapter.ts`、`history-projection.ts`、`legacy-history-projection.ts`、`models.ts` 及必要的共享来源模块；阅读锚点衔接涉及 `app.ts`，复用 `chat-projection.ts` 的 SDK 解析和工具身份。
- 沿用现有 HTTP/RPC、分页预算、Run 范围读取和可选字段；不新增协议版本、私有历史格式、宿主依赖或 Agent 准入门槛，不修改 SDK 原文和业务数据库。
- 更新嵌入浏览器资源与 Linux Core/CLI；MicroVM 使用既有构建打包入口交付新 GUI，保留真实构建身份和依赖许可证，不修改 MicroVM 运行机制、不发布镜像。
- 不以升级已有 Work Agent、修改默认镜像、清空历史或重建 Session 作为修复。真实会话仅只读验证，不调用真实模型；不扩展为整机重启或批量性能验收。
