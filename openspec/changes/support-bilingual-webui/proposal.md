# Proposal

## Why

Desktop 工作台、Serve 管理界面与引导目前以英文显示，现行规格也将多处界面文字限定为英文，中文使用者无法完整理解操作和恢复提示。需要支持中文和英文，并确保后续新增或修改的界面功能同时维护两种语言。

## What Changes

- 为现有 Desktop UI 和 Serve UI 的产品自有界面提供简体中文与英文，包括登录、首次初始化、快速配置、工作台、管理、状态、表单、错误和无障碍名称。
- 默认跟随浏览器，可从统一的地球图标语言入口选择“跟随浏览器 / 简体中文 / English”；轻量选择浮层取代常驻语言按钮。首次访问按浏览器语言偏好自动选择；在菜单中提供语言选择，并在当前浏览器保存显式选择。托管 Desktop、管理和引导共享同源偏好，独立 CLI Desktop 使用其来源的偏好。
- 保留现有草稿、身份、任务和 Service 工作区语义，切换语言不触发业务操作。用户内容、资源名称、日志、已有版本更新日志正文、协议值及技术标识保留原文；外部 Service 界面由其自身负责。
- 建立可维护的两种语言资源、参数一致性与界面文案检查，将相关检查接入常规构建或测试；后续新增、修改用户可见产品界面时同步交付中英文。
- 调整现行规格中限定英文的界面要求，保留其业务、状态、认证和恢复行为。

### 规划假设

- 中文版本先按 `zh-CN` 简体中文规划；英文使用 `en`。浏览器中文语言映射至简体中文，无法匹配时使用英文。后续扩展繁体中文不在本次范围内。
- 语言偏好保存在浏览器来源内，不随账号跨设备同步。登录和首次初始化页需要可发现的语言菜单，确保登录前可切换。

## Capabilities

### New Capabilities

无；本次扩展现有 UI 及其所属业务规格。

### Modified Capabilities

- `ui-language`: 两种界面语言、语言选择、内容边界及后续双语维护检查。
- `desktop-ui-language`: Desktop 的中英文产品文字、状态、控件和无障碍名称。
- `desktop-webui`: 工作台现有流程及反馈遵循选定语言，保留操作语义。
- `serve-ui`: 管理界面、菜单、反馈与确认遵循选定语言。
- `serve-ui-configuration`: 运行时和管理状态使用选定语言。
- `serve-ui-packages`: 包来源、操作阶段与恢复提示使用选定语言。
- `serve-ui-users`: 用户管理的状态与确认使用选定语言。
- `web-onboarding`: 登录、首管理员和快速配置的双语引导及语言菜单。
- `product-release-info`: About 与更新日志入口的界面标签遵循选定语言，版本正文保持现有数据语义。

## Impact

- 影响 `apps/desktop-webui/`、`apps/console-webui/`、共享 UI 构建输入、内嵌资源同步、相应浏览器测试及检查入口；登录和引导静态资源的 Go 路由需要涵盖新增资源。
- Core、CLI、WebUI 的业务协议、用户数据和已有发行制品身份保持原样；语言选择不需要新服务端 API 或运行时外部服务。已有版本的更新日志正文按返回原文显示。
