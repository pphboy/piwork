# Proposal

## Why

当前 Desktop 已具备生命周期、文件与包传输能力，但本次源码审查和合成浏览器复现发现，部分日常流程会丢失用户原目标、误选旧快照或让辅助读取阻断可用工作区。用户明确希望先修复已证实的问题，再以实际使用任务为中心减少无必要步骤；本变更据此区分 Bug、用户指定目标与设计改善，保留必要确认和安全边界。

## What Changes

以下保留2026-10-12提案时按使用模块说明的计划范围。Apply已启动，A/B/C前端实现已按最新main整合，当前可执行验收与保留门槛单列，环境/工具限制单列，逐项状态以 `tasks.md` 和[验收记录](evidence/acceptance.md)为准。修改范围是Desktop界面及对应测试，不改Core业务逻辑或API。

### 1. 导出与下载

**修改内容**
- 现在生成导出包后，还要进入操作详情、查看包、再点下载。改为一次明确的“导出当前内容并下载”，连续完成生成、校验和发起下载。
- 运行中的 Work 保留一次“停止并导出”影响确认；确认后接着完成导出，不再让用户停止成功后重新找入口。
- 已有旧包时仍能重新导出当前内容；查看指定快照时只打开该快照，避免拿错版本。
- 关闭进度窗口只收起展示，不丢掉原下载目标；准备完成后继续交付，并保留同一文件的手动下载按钮。

**范围**：导出入口、进度面板、快照选择和下载恢复。保留停止确认、文件完整性校验和身份隔离；只提示“已发起下载”，不承诺浏览器已保存到磁盘。不增加跨关页或程序重启的后台续传。

### 2. Work 列表与导航

**修改内容**
- 现在返回列表可能一直看到旧内容。改为返回列表或重新显示页面时更新一次，并提供手动刷新入口。
- 现在重进 Work 常回到 Services。改为优先回到上次使用的 Chat 或 Files，以及仍有效的文件位置。
- 现在再次 New Work 会带入上次名称和高级设置。改为上次创建可靠受理后，下一次使用新草稿；失败或结果未知时仍保留原输入。
- 启动成功后直接提供“打开 Work”。导入成功时说明“已导入，尚未启动”，由用户选择“启动并打开”或暂不启动。

**范围**：Work 列表、新建表单、进入与返回、启动及导入结果页。区域记忆限当前页面与当前身份；不自动启动导入内容，不改 Work 生命周期规则。

### 3. Service 应用与管理

**修改内容**
- 现在一次临时状态读取失败可能让整个应用区消失。改为保留已打开的应用和聊天区域，就地提示状态暂未确认。
- 服务从启动中变为就绪后，自动接上当前应用入口，避免一直停在“正在打开”。
- 日志慢或读取失败时，仍能进入服务详情并使用符合条件的控制；日志单独显示错误和重试。
- 启动、重启或重试服务后，保留原服务上下文和访问入口；修正“正在启动”却说明“已禁用”等矛盾文案。

**范围**：Service 视口、入口准备、详情、日志和控制结果展示。真实停止、删除或权限失效时仍撤销访问；保留画面不等于继续授予权限，不改服务后端控制逻辑。

### 4. Files 文件操作

**修改内容**
- 扩大文件复选框的可点击范围；首次选中或清空选择时，工具栏不再把文件行推走。
- 重命名预填原文件名，方便只修改需要的部分并保留扩展名。
- 复制、移动、删除失败时，直接在当前弹窗显示具体路径和原因，不再要求用户先关闭弹窗找结果。
- 文本编辑器增加“下载已保存版本”，无需返回列表寻找下载入口，也不会先自动保存草稿。

**范围**：文件列表、命名与操作弹窗、文本编辑器。保留覆盖、删除和未保存确认；未知结果先核对，已成功项不盲目重做。批量混合成功/失败仍需补实际测试，不把已有单文件失败截图当作批量验证；本次不扩展目录选择器。

### 5. Chat 与设置导航

**修改内容**
- 把未发送的文字和图片草稿纳入刷新、离开页面时的提醒，减少无提示丢输入的风险。
- “Open brain source”改为真正进入当前 Work 的 Files 并打开目标源码；有未保存设置时，先处理原有离开确认。

**范围**：聊天草稿离页保护、设置到文件的导航。保留现有聊天、图片和模型设置行为；不新增聊天内容或图片的永久本地存储，不承诺强制关页后恢复草稿，不自动保存设置或 Apply。

### 6. 弹窗、按钮与键盘操作

**修改内容**
- 补清楚搜索框和聊天输入框的键盘焦点；修正 Remove 按钮被显示成普通链接颜色的问题。
- 新建文件夹和重命名弹窗打开后直接聚焦输入；普通 Enter 提交一次，中文输入法确认候选时不误提交。
- 只对无草稿、非忙碌的轻量菜单和信息窗增加点击外部关闭。
- 把“关闭详情”和“取消执行”的按钮文案分清，避免两个含糊的 Cancel 并排出现。

**范围**：对应控件的局部样式、焦点、快捷键和文案。保留现有界面风格；停止、删除、覆盖、丢弃编辑、导入等确认不套用轻触关闭或通用 Enter 提交。

### 7. 加载、动效与无障碍：先验证

**修改内容**
- 检查快速、缓慢和长时间等待时，加载提示是否清楚、按钮位置和焦点是否稳定。
- 复核自动检查暂停后的状态与按钮是否一致。
- 验证现有“减少动态效果”设置，以及真实屏幕阅读器中的聊天和状态播报。
- 只有复现具体问题后才做对应的小范围修正；符合现有规则的部分保留。

**范围**：这是验证门槛，不是已经确认的整套缺陷，也不承诺新增装饰动效或重做无障碍系统。无法实际验证的项目明确保留为未测。

后续实施仍按“导出下载 → 工作连续性 → 交互细节”的依赖顺序推进，每组先复现、再修复、再验证。提案交付时仅有规划、全部实现任务未完成；此后已按明确请求启动Apply。当前完成状态按任务文件记录，不由本范围说明推断。

这些界面调整服务于“打开 Work → 使用 Service → Chat 改进 → 继续使用”的主流程。Request 是跨执行的业务目标，Run 是一次执行，配置和技术细节是辅助信息。NoDocker、Core/API/依赖/安全边界不变，原17项未测保持；新增实现与验收按 tasks 的后续章节单独记录。

## Capabilities

### New Capabilities

无。沿用现有 Desktop 能力，不新增后端任务系统。

### Modified Capabilities

- `desktop-webui`：细化工作区导航、草稿、创建、Service、Files、脑包导航及任务出口；修改 DWUI-009、012、013 的逐段操作/关闭后禁止自动下载契约，允许同一有效身份内已明确授权的一次导出交付持续完成，同时保留原对象恢复与隔离。
- `browser-service-access`：细化 BSA-005 的 Service Ready 后入口准备与暂时观察失败下的视口保留；原授权、origin、连接撤销与嵌入限制不变。
- `desktop-ui-language`：调整 DUL-002、007、009、015 的区域恢复、实用控件、导出连续流程和文件任务规则；保留现有英文 UI、局部反馈、合并 Response settings、确认及无障碍语言。

## Impact

- 主要模块：`apps/desktop-webui/src/{app,adapter,models,lifecycle,action-state,observation,images}.ts`、`public/style.css` 和相应状态/浏览器测试；仅必要时为原传输恢复补充 Go CLI 契约测试，复用现有 Core/CLI/WebDAV 接口。构建时同步 Desktop Go 嵌入资源，不手改生成副本。
- 使用与验收说明：维护本变更 `evidence/usage.md` 和 `evidence/acceptance.md`，不重建根 `docs/`；若触及用户入口 README，两种语言一起维护。保留本次审查编号/证据等级，不把源码推导、合成 fixture、真实后端结果合并成一个“通过”。
- 在途变更：以现行主规格为底，保留 `fix-webui-data-integrity-and-recovery` 的条件写入、统一配置草稿、匿名 Inspect 恢复，以及 `compact-chat-composer-settings` / `improve-desktop-chat-and-release-info` 已实现的设置/图片契约；不重复实施或代为归档，不让较旧 delta 覆盖现行规则。
- 环境边界：当前采用 NoDocker 开发。提案阶段要求Apply前准备仓库要求的Go1.25.5、原生CLI和合法浏览器验收环境；现有构建及分层执行结果见验收记录。真实 Core/Docker 包生成、校验与停止链路仍为未验门槛，不自动启动 Docker，不以合成下载事件冒充真实端到端验收。
- 本轮不修改 Core 业务逻辑或 API；若验证发现现有接口不足，先另行提交证据和必要变更供用户确认，不自动扩大。既有 Go/CLI 契约测试与正常资源构建同步可执行。其余不新增宿主运行时依赖、Core API、永久传输队列或跨进程自动续传；不自动启动导入 Work、不合并 Save/Apply、不删除停止/覆盖/删除确认、不绕过权限或完整性校验，不修改其他在途 change 的文件。

## 2026-10-14 直接反馈：控件语义与关闭残影

本轮纠正已授权实现：Show/Hide Chat 在同一固定工具栏位置使用一致面板图标按钮；Files 的＋是锚定非模态动作菜单，New folder 才打开输入确认窗；正常配置只显示状态与刷新，不保留无有效详情的 Details；彻底移除Modal动画、退场快照与延迟清理，立即释放背景交互。相邻 Input options 入口不冒充开关，Move 不使用返回箭头。保留身份、草稿、iframe、危险确认及 Save/Apply 分离；不修改 Service 业务页面、Core/API/依赖。

## 2026-10-14 浮层职责与Service局部控件

按用户明确规则修正已有入口：账号/Work/Agent/Service/文件更多操作为锚定Dropdown；Service选择、模型与简单输入设置为非阻断Popover；持续Service管理/详情为Drawer；删除/停止/覆盖确认、导入及独立长表单继续Modal。信息提示只解释所属元素，不承接操作。Show/Hide Chat从Work导航下移到Service Header同一控件，窄屏保留可见的同层恢复出口。保留无Modal动画、原安全/身份/草稿/iframe/写锁，不修改Service业务内容、Core/API或依赖。
