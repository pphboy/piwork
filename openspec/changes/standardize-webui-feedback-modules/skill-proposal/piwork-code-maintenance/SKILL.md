# Piwork 项目维护

> 这是正式 OpenSpec change 内的实施候选，尚未安装。正式目标：`.agents/skills/piwork-code-maintenance/SKILL.md`；`AGENTS.md` 仅增加短触发入口。当前正式生产规则仍以仓库现有入口与有效 OpenSpec 为准。

## 先找到责任，不先读整个应用

1. 确认当前用户授权、所属 OpenSpec change 和相关需求。原型/设计认可不自动授权 source、Skill、检查配置、归档或发布。
2. 从 [选择性维护入口](references/module-map.md) 只取本次代码/配置/协议生成/文档/UI 类别；WebUI 任务才展开其详细条目。先读责任模块的公开接口与相关测试，再按实际影响追踪必要调用方；不要默认读取整份 app、生成资源、全部 reference 或历史归档。
3. 改前在所属 change 的已有设计/任务中用最短说明确定：影响哪些层、权威来源与状态谁负责、输入/输出与直接消费者、同步哪些生成物/双语说明、执行什么检查；不适用项说明依据。不为小改动制造固定层数或额外设计文档；必要决策归所属 change。

## 边界优先

- 同一状态有一个写入所有者。跨模块只读快照或调用具名操作；不传整份应用 state/adapter，不借任意字段 getter/setter、服务定位器或巨型 context 绕开边界。
- 共享展示不导入具体 app/feature/adapter；feature 不导入入口；新增依赖不得形成循环。Go 沿现有 package 职责组织，接口由实际消费需求决定，不为每个函数强制套接口。
- 菜单明确区分 global-account/work-row/work-header/service，显式传目标与权限；不从全局选中项推测，不把行与头部菜单混用。
- 先复用有效接口。导出继续由 ExportFlows 协调；UI 关闭与业务取消、请求 busy 与已接受任务、明确失败与未知、修改确认与后续刷新分别处理。
- 抽取先保持行为，再应用获批产品变化；旧行为只保留一份活动实现。不能把多个文件重新接回一个万能 state，不能以文件长度代替职责判断。

## 配置、生成物和文档同样有边界

- 配置改动一起核对默认/缺省、显式值、优先级、校验、未知/弃用键、兼容及生效范围；不把保存当 ready/Apply，不擅自启用旧环境键。沿真实消费者同步 UI、帮助、部署/示例，不复制新的默认值来源。
- 协议、HTTP DTO、history、UI 嵌入和部署材料从各自实际源生成；用对应生成链和契约正反例查陈旧输出，不反向只手改 generated 文件。冻结原型、证据和已发布身份不被再生成覆盖。
- 文档归属遵守 RDOC 与有效 delta；README 保持精简，教程进既有部署/官网入口，中英文含义/命令/导航同步。当前链接和支持行为过期要在范围内修复；历史记录、产品 brain.md/Skill/模板不是待清理的开发笔记。
- 结束前核对本批重复实现、无消费者配置、失效入口和说明。先确认兼容/归属再按授权清理；无关问题不扩大本批，本批阻塞不隐去。只用合成夹具，不读/记录真实秘密；不因防腐自动发布或执行真实用户安装。

## 同一产品与代码风格

遵循仓库已有 formatter/build 配置及相邻有效约定；Go 用 gofmt。TS/JS/CSS 的新增统一配置须在获批范围内确定，不顺便全仓重排。UI 遵循现行 component spec、共享 tokens/controls 和双语资源，语义图标、控件密度及状态表达共用来源；页面布局不强行统一。紧凑模板不能以压成大段单行代替模块接口；也不为达任意行数而拆碎有内聚性的代码。

## 用证据检查维护成本

- 新增/抽取单元直接 import 模块测试，使用窄 fake port；不要读取大入口源码、正则抽函数或注入跨功能全局才能测该单元。保留浏览器集成测试。
- 用负例验证本批依赖检查会失败；检查职责/接口、反向与循环依赖、跨所有者写入、重复活动实现及必要安全不变量；先对本批触达范围执行，不借治理名义扩大重构。
- 在所属 change 记录实际读取的模块/行范围、必要外部依赖、被迫涉及的无关功能及验证结果。若局部改动仍需理解整个应用，说明未完成边界并收口；不编造 Token 节省，不规定固定文件数/行数。
- 复用既有 native-boundary、repository-docs、docker-quickstart、ui-language 和 Makefile 检查，按影响选择；对新增规则加入确实失败的合成负例，不建平行规则或虚称 CI 已执行。
- 按 AGENTS 与本 change 运行相关 typecheck、单元/契约、浏览器、资源嵌入和文档检查；明确通过/失败/未执行。原型、静态检查和模拟端口不能替代真实集成验证。
