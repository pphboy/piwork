# piwork demo

piwork 架构的最小地基:**一个 pi daemon + 一个 CLI**。daemon 内部用
[pi coding agent SDK](https://pi.dev/docs/latest/sdk) 跑 agent session,对外只暴露 **gRPC(HTTP/2)**;
CLI 是 gRPC client,形态是**问答循环**。

端口默认 `8083`,与设计稿里每个容器的端口一致。proto 保留了 `session_id`,后续接 ppkg / 多容器
不需要改协议。

```
┌──────────────────┐   gRPC (HTTP/2)    ┌────────────────────────────────────┐
│ piwork-cli       │  Health (unary)    │ pi daemon                          │
│  · 问答循环       │  Ask (server       │  service.ts   gRPC 语义/错误映射      │
│  · health        │   streaming)       │  pi-backend.ts  ← 唯一接触 pi SDK 处  │
│  · ask (单发)     │ ─────────────────► │  session-registry.ts  会话生命周期    │
└──────────────────┘                    │  SessionManager → .piwork/          │
                                        └────────────────────────────────────┘
```

## 快速开始

```bash
cd demo
npm install
npm run proto:gen      # 生成 src/generated/piwork.ts(产物已入库,通常不必重跑)
npm run build

cp .env.example .env   # 填入 ANTHROPIC_AUTH_TOKEN / ANTHROPIC_BASE_URL 或 API key

npm run daemon         # 终端 1
npm run cli            # 终端 2:进入问答循环
```

其它用法:

```bash
node dist/cli/main.js health                       # daemon 自检:模型/鉴权/baseUrl
node dist/cli/main.js ask "什么是 gRPC"             # 单发,给脚本用
node dist/cli/main.js ask --session <id> "那 HTTP/2 呢"   # 续用已有会话
node dist/cli/main.js ask "..." --json             # 逐行输出原始 AskEvent
```

循环内命令:`/new` 换新会话、`/session` 查看当前会话、`/help`、`/exit`。
**回答中**按 Ctrl-C 取消本次回答(daemon 侧会 `session.abort()`);在提示符下按 Ctrl-C 退出。

## 配置

`.env` 由 daemon 启动时用 Node 内置的 `process.loadEnvFile` 加载;所有项都有默认值。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `ANTHROPIC_AUTH_TOKEN` | - | pi 原生识别,作为 `Authorization: Bearer` 发出(适合 token 型代理) |
| `ANTHROPIC_BASE_URL` | - | 代理地址,经 daemon 写入 `models.json` 后生效(见下) |
| `ANTHROPIC_API_KEY` / `PIWORK_API_KEY` | - | 走 `x-api-key` 的普通 key,优先级低于上面两项 |
| `PIWORK_HOST` / `PIWORK_PORT` | `127.0.0.1` / `8083` | 监听地址 |
| `PIWORK_MODEL` | 第一个可用模型 | 形如 `anthropic/claude-opus-4-5:high` |
| `PIWORK_TOOLS` | `read,bash,edit,find,ls` | 逗号分隔。设为空值或 `none` 可**关闭全部工具** |
| `PIWORK_AGENT_DIR` | `.piwork/agent` | auth.json / models.json 位置 |
| `PIWORK_WORKSPACE` | `.piwork/workspaces/default` | 新会话的 cwd |
| `PIWORK_LOG_LEVEL` | `info` | `debug` / `info` / `warn` / `error`,日志走 stderr |

## 工具与安全边界

默认启用 `read`、`bash`、`edit`、`find`、`ls`。**pi SDK 里没有任何审批环节** —— 我把 SDK 的
工具执行路径检索了一遍,不存在 approval / permission / requiresApproval 之类的门控,唯一的拦截点是
extension 的 `tool_call` hook,而本项目不加载任何 extension。也就是说:

> **`bash` 会直接执行命令,`edit` 会直接改文件,不会询问。**

能约束它的只有 cwd:每个 session 的工作目录是 `PIWORK_WORKSPACE`(默认
`.piwork/workspaces/default`,一个空目录),单次会话可用 `--cwd` 指定。注意 `bash` 拿到的是真实
shell,能 `cd` 到别处,所以 cwd 只是起点而不是牢笼。

要收紧:

```bash
PIWORK_TOOLS=read,find,ls        # 只读,去掉 bash 与 edit
PIWORK_TOOLS=none                # 全关,退化成纯问答 agent
```

`find` / `grep` 一类工具遵循 `.gitignore`,被忽略的文件不会出现在结果里。

## 一个必须知道的坑:baseUrl

**pi 不读 `ANTHROPIC_BASE_URL`。** 它内置的 provider 把 base url 硬编码为
`https://api.anthropic.com`,全量检索 pi-ai 编译产物只有 `AZURE_OPENAI_BASE_URL` 这一个 base-url
环境变量。

所以 daemon 启动时会把 `PIWORK_BASE_URL` / `ANTHROPIC_BASE_URL` 物化成
`.piwork/agent/models.json`:

```json
{ "providers": { "anthropic": { "baseUrl": "https://your-proxy" } } }
```

provider 级 `baseUrl` 会覆盖其下**所有**内置模型的 base url,这是让代理生效的唯一途径。

该文件带 `// generated by piwork daemon` 标记;**若同名文件由你手写(无标记),daemon 绝不覆盖**,
只在日志里告警。改了 `.env` 里的地址后重启 daemon 即会重写。

排查代理问题:`node dist/cli/main.js health` 会直接打印实际生效的 `model`、`auth source`、`base url`。

## 协议

```proto
service PiDaemon {
  rpc Health(HealthRequest) returns (HealthResponse);
  rpc Ask(AskRequest) returns (stream AskEvent);
}
```

`Ask` 是 server-streaming,CLI 逐字打印而不是等整段生成完。

**错误语义**(有意划清,避免二义):

| 时机 | 通道 | 例 |
| --- | --- | --- |
| 请求被接受**之前** | gRPC status | 无凭证 → `UNAUTHENTICATED`;会话忙 → `FAILED_PRECONDITION`;空 prompt → `INVALID_ARGUMENT` |
| 已写过 delta **之后** | 流内 `AskEvent.error` | 此时 HTTP status 已提交为 OK,无法再改 |

`AskEvent` 是 oneof:`session_started`(总是第一个,带回 session id)、`text_delta`、
`thinking_delta`、`tool_start` / `tool_end`、`result`(成功时最后一个)、`error`。

## 代码结构

```
proto/piwork.proto              协议单一事实来源
src/generated/piwork.ts         ts-proto 产物(入库,保证无 protoc 也能 build)
src/common/                     config(env 解析)、logger(结构化日志 → stderr)
src/daemon/
  main.ts                       入口:.env → models.json → server → 信号处理
  models-json.ts                让代理 baseUrl 生效(纯函数可测)
  pi-backend.ts                 唯一 import pi SDK 的文件
  event-mapper.ts               pi 事件 → AskEvent(纯函数,单测主要目标)
  service.ts                    gRPC 语义:status / 流内错误 / 取消
  session-registry.ts           会话生命周期(不依赖 pi)
  server.ts / agent-backend.ts  gRPC server、backend 接口
src/cli/
  main.ts / args.ts / repl.ts   入口、参数解析、问答循环
  client.ts                     gRPC client + 流适配为 async iterator
  render.ts                     AskEvent → 终端输出
```

pi SDK 只出现在 `pi-backend.ts`。事件映射与配置解析是纯函数,`service.test.ts` 会在临时端口上
起真实 gRPC server 验证错误语义。
