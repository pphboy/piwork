# NiceGUI Web application

This editable application uses environment contract 2 of `piwork-web-base`: Python 3.13, NiceGUI and SQLite, with standard packages already installed. The image contains no business application. Its source is `deploy/images/web-base/` in Piwork; `references/web-base.json` distinguishes the local candidate from an available published fixed tag@digest. Explicit local acceptance can select its verified prebuilt image; an unpublished reference is not a usable published default.

Read SPEC.md, then invoke `node <loaded-skill-directory>/initialize.mjs --template web-app --name <service-name>` through authorized Agent bash. Use `--template workstation` for that example. The initializer exclusively creates the target, refuses every existing directory/file/link before writes, writes Spec first and copies writable files. A failed initialization must not continue to Service creation or restart. Maintain existing applications by reading their actual Spec/source and making targeted edits.

Set the Service command to `/usr/local/bin/piwork-web`, args `["run", "--app", "/var/data/workspace/apps/<service-name>"]`, a read/write workspace grant, web TCP 8080 and HTTP `/health` readiness. Source, checks and caches belong in `apps/<service-name>`, business data in `data/<service-name>` using the injected Service name. Service memory is unlimited; query the actual CPU/count context. Identity/CA come only from `/etc/piwork/interaction`; browser code never receives the token.

`prepare`, `check`, `serve`, `run` and `dev` are Service-base commands. Standard apps reuse the image without a full venv, npm install or frontend build. `run` checks changed input and reuses valid checks for unchanged restarts. `dev` explicitly enables Python reload. Agent writes source and uses the existing Service command/Operation; these commands and pip are not available in Agent bash.

Extra exact Python pins or app-local wheels belong in `requirements.in`. Explicit `run --install-deps` prepares an application-local `.deps/` environment inheriting fixed standard packages, retains `requirements.lock` and exact offline wheels, and verifies installed dependencies. Conflicts/failure keep the old effective environment and data. Matching restarts/imports need no registry download; lost/relocated environments are recreated from retained materials. Do not modify global image packages or request Docker exec/build.

After edits Pi completes checks and the existing Service update/restart, observes the original Operation and verifies actual codeVersion and business output. NiceGUI pages read safe versions automatically, re-establish their client after ready updates, restore the supported nonsecret Todo-title draft and current path, and refresh shared data. Failed checks or disconnection do not cause reload loops; failed draft preparation keeps input and retries. Application updates do not Apply brain/Work configuration or refresh the Desktop shell.

Page identity includes the default `app.py`, `ui.py`, `page-client.js` and `style.css` when present. Add page helper modules and local browser resources to `page-files.json`, for example `{"files": ["pages/header.py", "assets/theme.css"]}`. Keep that list and SPEC.md current when splitting pages or adding/removing resources; keep independent business modules, data, caches and dependency environments out. Paths are app-relative regular files; invalid, missing, escaping or symbolic paths fail checks/startup. Existing apps without a manifest retain the default set. Changing a listed helper/resource changes frontendVersion; changing only business code leaves frontendVersion stable.

The sample shares Todo/review/export logic with Agent Queries/Actions, including expectedStateVersion, original idempotent Action/Job results and transactional outbox. Feedback alone requests Pi work; ordinary visits/data events do not. Imported old events/Jobs do not replay. The workstation variant intentionally omits completed items until repaired; the general starter begins with them included. Replace these sample objects with the requested domain.

Implementation: `app.py` registers HTTP/protocol routes and lifecycle; `ui.py` renders pages; `workstation.py` holds authoritative business state; `piwork_protocol.py` implements interaction/outbox. `style.css` is editable local styling. Page/runtime helpers come from the fixed image. The real sqlite3 CLI exists in both Agent and base, while ordinary business changes use Query/Action contracts.

Custom classes use the `webapp-` business prefix and are scoped to the application root; retain framework layout classes. Query failures preserve last confirmed content and drafts with a data-status notice; recovery clears that notice through the existing timer.
